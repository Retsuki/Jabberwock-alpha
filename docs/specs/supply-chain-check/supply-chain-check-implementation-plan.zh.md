# 供应链检查实施计划

[English](supply-chain-check-implementation-plan.md) | 中文

> 分三个阶段实现已批准 B：固定 Host 扫描与持久化、对话／表格／报告 UI、验证。复用 Session、jobs、工作区导航和报告组件。无需数据库迁移、大模型依赖或自动包变更。

## 范围与负责人

遵循[规格](supply-chain-check-spec.zh.md)。Host 实现负责扫描器约定、锁文件解释、注册表事实与持久化结果。UI 实现负责侧边栏入口、对话事件展示和报告导航。实现使用方之前先约定结果／事件类型；实现期间可细化 API 名称。

## 阶段 1：约定与 Host 扫描器

- [x] 与 Host 负责人定义 `securitySupplyChain.start/read/cancel` 身份、幂等性、运行状态、进度事件和结果行。保留 Workspace／Gateway 授权及 Host 负责的路径解析。
- [x] 使用现有 `ctx.jobs.start` 的取消／生命周期支持与持久化 Session 事件增加固定扫描器服务；临时 job 不是结果存储。将类型化运行快照保存为既有 `user/message` 提示（`security-supply-chain`、`form=notice`、生成方 `visibleInHistory:true`），并通过 jobs 等待以抑制模型唤醒。通过 `packages/api/session-controller/src/commands.ts` 创建工作区对话。
- [x] 解释 npm／pnpm 锁文件、共享工作区范围、直接／间接依赖及生产／开发分类，不安装或执行项目代码。
- [x] 以有界请求和输出查询 npm 注册表公告事实。可通过固定主机、无 token 的 GitHub advisory 查询补充公开 GHSA ID；失败保留未知字段，不隐藏注册表发现。
- [x] 保存已安装／修复版本、严重程度、来源 URL／标识、公告日期、一般影响／依据，以及独立分级的项目影响。不得根据静态导入推断已确认影响。
- [x] 用聚焦 Host 测试覆盖取消、超时、锁文件缺失／不支持、响应不完整、注册表失败和重复／并发请求。

- [ ] 重新记录英中文档配对并验证受影响链接。不得提交或推送。

## 约束

扫描器不得安装、修复或更新依赖，不得运行任意 shell 命令、执行载荷或攻击目标应用。事实结果无需大模型输出。公告匹配不证明可达性或安全；缺失信息必须明确。本计划不代表实现或验证已经完成。
