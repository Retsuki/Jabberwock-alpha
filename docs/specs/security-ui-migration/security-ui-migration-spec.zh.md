# 安全界面迁移规格

[English](security-ui-migration-spec.md) | 中文

> 10 秒速览：使用现有界面组件将原型安全工作区整合到 Jabberwock。用户无需单独运行 Next.js 服务即可查看项目、资产、诊断任务、发现和代理。本阶段使用演示数据，不执行安全测试。不计划更改 Host 数据库或 Session 格式。

## 范围

本参考文档定义已批准的界面迁移。来源为 `jabberwock2/frontend`：其存储使用 `artex-state-v1` localStorage 和模拟 AI 响应；Hono 后端仅返回问候语。目标为 `packages/client/ui-security`，通过现有各工作区与项目行下的折叠菜单以及 `security` 主面板呈现。现有聊天功能保持独立可用。

## 用户流程

1. 在左侧栏现有工作区与项目下展开 Security。
2. 选择 Assets、Tasks、Vulnerabilities 或 Agents，打开对应工作区的安全视图。独立安全项目选择器不再作为入口。
3. 注册目标并查看任务或发现详情。空列表和未知选项提供返回对应列表的路径。
4. 返回 Chat，不替换或提交当前会话。

任务详情在现有界面组件足够的情况下复用已有概览、会话历史、探索、时间线、发现、复测、资产、审批和报告信息。演示控件不得暗示实际扫描、审批、代理执行或报告导出已经发生。

## 数据与安全

安全数据按现有工作区 ID 隔离，与 Session 历史和 Host 凭据独立。`sidebar.workspaces.project.children` 插槽传入工作区 ID 和显示标题；安全功能的私有导航选择工作区 ID 与视图。存储继续使用 `jabberwock.security.v1`，项目 ID 为 `workspace:${workspaceId}`。折叠菜单紧接展开的实际工作区项目行呈现；虚拟文件夹、未分类项和扁平分组不显示该菜单。选中样式要求工作区与视图匹配且安全面板可见。标题通过 `useWorkspaces` 跟随当前工作区名称。新工作区从空状态开始。保留现有 `jabberwock.security.v1` 值，包括独立的 Acme/internal 演示项目；不删除它们，也不将其分配给任意工作区。存储失败必须可见，不得声称已成功持久化保存。无效保存数据不得被静默覆盖。本阶段不连接目标、不请求模型、不启动子进程，也不改变权限。

原型的浏览器源拥有其现有存储。迁移不得假设 Electron 源可以读取它。保留 `artex-state-v1`；在保存数据和参考资料的保全方式确定之前保留原型。本阶段不承诺自动导入旧浏览器数据。

## 暂缓事项与验收

不添加 shadcn、Tailwind 或 Base UI。暂缓 G6 覆盖图和原型专用聊天。需要新增组件依赖的其他界面应记录下来，供用户后续审阅。实际诊断、AI 规划、流式工作代理和安全审批执行需要单独设计。

验收需要在桌面检查工作区折叠菜单导航、资产注册、详情、空状态、工作区隔离、旧值保全、重新加载后的持久化以及窄屏布局；现有聊天必须保持可用。未观察的检查在[实施计划](security-ui-migration-implementation-plan.zh.md)中明确保持待办。只有完成迁移验证并保全所需数据与资料后，才可将 `jabberwock2/` 移到废纸篓。未授权永久删除。
