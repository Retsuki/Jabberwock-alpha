[English](security-skills-verification.md) | 中文

## 摘要

产品在 `ui-security/assets/security-skills` 同捆五个工作流，复用现有注册表和加载器，并通过现有规划归属服务公开仅规划控制。包归档包含全部五个 `SKILL.md` 文件和共享指令。无需安装仓库本地开发技能。

## 自动化证据

2026-10-20，14 个文件中的 206 项针对性测试通过，涵盖技能策略与卸载、Loader 注册、跨工作区查询、仅规划路由、有界失败、原生宿主工具、取消、恢复目录和现有设置准入。产物构建通过七项检查；随后聚合构建检查通过两个编译器检查。五项技能格式验证和五对相关文档验证通过。持久化验证将 70 个根与 20 条历史记录匹配；未更改持久化记录格式。

## 已观察到的限制

`task.setup.limits` 是说明文字。新执行的上限来自 Host 配置；恢复执行保留已保存的上限。控制读取公开两者，调查工作流在分派前检查，而不声称文字会更改执行预算。按任务配置机器强制执行上限不属于本次变更。

现有所有者意图解析器会拒绝包含某些否定词的整条消息，即使否定词用于限制目标而非取消调查。单独明确的开始指令到达现有执行服务；未放宽任何授权检查。

在首条消息之前立即选择 Codex 时，先产生 Claude 请求，随后才保存 Codex 选择。在现有模型选择代码中观察到此首轮选择行为，本次未修改。获得明确的一次性批准后，后续 Codex 请求完成，保存事件包含 `engine: codex` 和 `gpt-6-astra` 证据。截图：`/tmp/jw-security-skills-codex-verified-chat.png` 和 `/tmp/jw-security-skills-codex-verified-report.png`。

仓库级包检查仍报告已有的订阅引擎发布元数据、web-fetch 包文件列表及远程 Client 项目引用不一致。安全包的资源分发检查通过。通用完整预检已中断；验证证据为上方针对性测试和明确执行的构建检查。
