# 安全工作流技能

[English](security-skills-spec.md) | 中文

## 摘要

> 提议的需求：Jabberwock 所有者可通过普通聊天创建安全任务、请求 Planner 计划、启动调查、查看进度和打开报告。产品内置技能指导现有服务，不实现另一套执行系统。不预设新的持久化格式。主要风险是选错任务、意外执行和提供商工具不可用。本文不包含实现。

## 所有者流程

所有者说“分析这个项目”。主 agent（智能体）解析当前 Workspace，读取已登记资产和现有任务，并区分本地源码审查与远程安全调查。明确的请求进入相关现有任务或新建草稿。agent 仅询问影响目标选择或执行的缺失信息；一般性请求不授予任意远程目标访问权。

agent 保存商定的目标、完成条件、范围、允许操作和限制。它复用已确认设置，不重复询问，同时保留 Host 授权检查。计划请求调用 Planner，不派发 Worker。明确的调查请求在满足准备条件后启动现有执行工作流。已有授权在其范围内仍可使用；如果 Host 要求当前指令而会话无法提供，agent 应解释具体要求，不得虚构同意。

创建后，agent 返回已保存任务的标识和导航操作；派发后，返回已接受运行的标识。它区分已接受、运行中、已完成、失败、已取消和已中断状态。之后的结果请求读取已保存证据并提供报告导航操作，不启动另一轮调查。

## 技能需求

以下名称为暂定。用户可显式调用技能，也可通过自然语言请求发现技能，无需学习这些名称。

| 技能 | 触发条件和结果 |
|---|---|
| `security-task` | 创建或配置诊断任务；读取当前任务及已登记资产，避免意外重复，保存草稿并返回标识和概览操作。 |
| `security-plan` | 请求 Planner 制定或修订调查计划；保存结果并返回状态，不启动目标操作。 |
| `security-investigate` | 委托调查；解析任务，检查准备状态和明确授权，启动或恢复现有 Planner/Worker 工作流。 |
| `security-status` | 解释当前进度、待审批项、失败和缺失条件；仅在请求时停止或向 Worker 发送指令，并明确接收者。 |
| `security-report` | 读取已保存结果并提供报告视图；总结证据、未解决发现和覆盖缺口，不把没有发现说成安全。 |

每个技能声明适用场景、不适用场景、前提条件、支持的工具、操作顺序、可观察的成功结果和恢复行为。共享规则只有一个维护位置，仅在需要时加载。没有任务时，调查技能可调用任务工作流；不得向内部 Planner 或 Worker Session 递归委托任务控制。

## 产品行为

技能随 Jabberwock 分发，在已登记 Workspace 的普通所有者聊天中可发现，包括 Jabberwock 源码目录之外的项目。仅安装仓库本地开发技能不满足此需求。技能描述和用户回复支持日语。仅加载相关工作流正文；工具输入、输出及模型可见的技能内容使用现有持久化 Session 机制。

每个执行引擎都检查能力可用性。可见技能必须具备所需工具，或明确解释不可用能力并提供现有任务页面入口。不得虚报操作成功、使用未公开的存储写入，或用 UI 自动化绕过缺失工具。提供商支持必须经过验证，不能由聊天能力推断。

报告显示指通过现有 UI 机制返回有效的任务报告导航操作。自动切换面板和文件导出是独立功能，不包含在此需求内。空结果、未完成、失败和截断状态保持明确；有界工具响应省略详情时，用户可打开完整保存视图。

## 现有操作和所需补充

现有[主聊天适配器](../../../packages/client/ui-security/src/security-chat-tools.ts)和[命令模式](../../../packages/client/ui-security/src/control-types.ts)提供 `list`、`read`、`create`、`update`、`start`、`resume`、`stop`、`message` 和 `open`。[操作服务](../../../packages/client/ui-security/src/security-control.ts)委托给现有责任方。技能复用这些操作及其修订检查和重试标识。

`message` 面向现有 Worker，而非 Planner。聊天命令集没有仅规划操作；实现 `security-plan` 需要基于现有规划服务提供明确的 Planner 操作。该命令集也不包含资产登记：未登记目标必须使用现有资产登记入口，不能虚构资产 ID。更广泛的资产管理不在首期技能范围内。

当前 Codex 驱动没有提供与 Claude 路径相同的原生 Host 工具桥接。在承诺等价行为之前，实现必须明确提供商能力矩阵和实际技能加载路径。提供商集成变更需要单独进行设计审查。本规格不指定新包、工具模式或数据库。

现有报告导航请求为：

```json
{"command":{"action":"open","taskId":"task-example","view":"report"}}
```

结果携带导航目的地和服务的序列化数据：

```json
{"action":"open","workspaceId":"workspace-example","taskId":"task-example","view":"report","data":"{}"}
```

上述结果仅演示信封字段；实际数据来自服务。仅规划请求的模式仍是待定设计，不是现有 API。

## 验收条件

- “分析这个项目”选择当前 Workspace 和正确任务工作流；本地与远程意图不明或多个任务匹配时，在修改前提出针对性问题。
- “创建任务”保存一个草稿，返回其标识，不发送目标请求；重试同一操作不会创建重复任务。
- “让 Planner 制定计划”记录规划活动并生成计划，不派发 Worker 或访问目标。
- 设置完整且已授权的调查请求仅启动一次；设置不完整时仅指出缺失条件，编辑冲突要求重新读取。
- “进展如何？”读取当前状态；停止请求等待现有停止操作，不提前报告完成。
- “显示报告”返回正确报告操作，保留已保存证据，不启动新运行；缺失和部分结果保持可区分。
- 跨 Workspace 标识、内部 agent 控制尝试、未登记资产和不受支持的提供商能力不能导致未授权操作或虚报成功。
- 支持的提供商分别通过已录制工具路由场景和真实模型端到端检查；GUI 导航经过目视验证。仅能加载 SKILL.md 文件并不足够。

## 范围和待定事项

首期范围为通过聊天编排安全工作流。不包含新诊断工具、无限制 shell 访问、自动源码修复、定时执行、外部报告分发或 ARTEX 功能对齐。本地源码分析不得静默变为远程调查。

实现前需确定支持的提供商、仅规划操作及技能分发和加载设计。技能名称可调整，但用户可见结果不变。本需求文档不授权运行时实现或发布。
