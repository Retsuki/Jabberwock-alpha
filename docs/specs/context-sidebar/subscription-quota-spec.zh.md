# 上下文与订阅用量

[English](subscription-quota-spec.md) | 中文

## 摘要

> 已批准方案 B：复用 Session 上下文测量，并增加共用的账户用量读取。用户在右侧上下文面板查看详情及订阅窗口，并在输入框模型控件旁看到紧凑的上下文圆环。无需更改 Session 持久化。提供方不可用及账户观测过期必须明确显示。

## 用户流程

用户打开会话后，在输入框右下方的模型控件旁看到上下文圆环。点击圆环打开现有右侧面板的用量详情。百分比表示所选会话当前的上下文占用，绝不表示订阅额度。

上下文面板保留上下文容量、可用的组成明细及累计 token 计数。在这些数据下方，订阅区域显示当前订阅提供方报告的用量窗口、已用百分比、重置时间及观测时间。只有提供方时长相符时才标为五小时或每周；其他时长保留实际数值。

切换提供方后，当前显示不再使用无关观测。未知值保持为不可用，有效的零仍显示为零。资源传输失败可将已有观测标为过期；提供方返回不可用则清空窗口。API 密钥路径不显示虚构的订阅额度。

## 数据归属

现有 Session 用量投影负责上下文占用、分类估算及 token 计数。订阅引擎服务负责只读账户用量：每次完成的读取均为全新观测，仅并发读取共享请求。界面组件使用同一账户结果，不分别调用原生提供方。账户观测不加入会话记录、模型输入或 Session 持久化。

Claude 读取结构化的实验性 SDK 用量信息，并跳过行为执行。Codex 读取官方 app-server 的账户速率限制响应。实现按每个返回窗口的时长分类，不假设主要限制总是五小时。模型专属限制属于可选的提供方数据。两个适配器均不通过本地 token 推算账户用量，也不扫描会话或读取凭据文件以获取限制。

## 失败与生命周期

认证不可用、提供方数据不受支持、超时及提供方失败均产生明确的不可用状态，不使会话轮次失败。采集有截止时间，并跟随服务取消和释放。认证变化取消此前连接进行中的请求；Host 不保留已完成的账户缓存。

## 验收

- 上下文为零、容量未知、超过容量及模型或提供方切换仍可区分。
- 账户用量为零、窗口缺失、时长未知、观测过期、刷新失败及账户断连均有明确显示。
- 从输入框打开上下文沿用现有侧栏生命周期与响应式布局。
- 定向测试及构建先于原生应用操作与截图；验证结果单独记录。
