# 常時表示コンテキストパネル仕様案

> 10秒サマリー: Jabberwockのチャット内右上に、実行エンジン・現在のコンテキスト・累積トークンの概要を表示する。デスクトップの通常幅では初期状態から開き、詳細サイドバーを開くと概要カードを隠す。CodexとClaudeの公式通知・SDK情報を保存済み会話へ関連づける。DB変更なし。取得できない値は未取得、推定値は推定と表示する。既存右パネルを活用するB案を採用し、Codexの角丸カードと区切り線を表示の参考にする。

## ユーザーフロー

1. 会話を開くと右側に使用量パネルが見える。既存セッションの閉じた初期状態も考慮する。
2. 上部にエンジンと実際のモデル、コンテキスト使用率・使用量／容量を表示する。
3. 会話が進むと公式通知に応じて更新し、更新時点を示す。未取得時は0とせず、応答後に表示される旨を案内する。
4. 入力・出力・キャッシュの累積トークンはコンテキスト占有量とは別の欄で確認する。
5. ファイルやターミナルは詳細サイドバーで開く。概要カードとは同時表示せず、閉じるとカードに戻る。

## 表示内容

- 実行エンジン、実モデル、データの更新時点。
- 現在コンテキストの使用量／容量、使用率、残り。容量0や未取得では除算しない。バーは100%で止めても、上限超過の数値は隠さない。
- 会話全体の累積入力・出力・キャッシュ読込・キャッシュ作成。reasoningは出力の内数として重複加算しない。
- 取得可能なカテゴリ内訳。Claudeのmessages/tools/memory/skills等は公式SDKの分類を使用し、deferredはコンテキスト使用量へ加算しない。利用した集計方法と推定の有無を示す。
- Codexが提供しないカテゴリをClaude風の比率で捏造しない。サブスクの残り契約枠とコンテキストの空き容量も混同しない。

## データの扱い

Codexはapp-serverの thread/tokenUsage/updated 等を受信する。Claudeはassistant/resultのusageとSDKのcontext usage情報を利用する。累積値・直近要求値・再開時復元値の意味を分離し、結果の累積カウンタを毎回足し直さない。SDKの推定費用を実際のサブスク請求額として表示しない。

ClaudeのgetContextUsageはsummaryを優先し、カテゴリごとのtoken-count APIを常時呼ばない。現在の実行プロセスの寿命内に取得し、取得失敗は推論そのものを失敗させず未取得として示す。エンジン切替時に前のエンジンの使用量を現在値として見せない。

既存tokenUsage・contextPressure・contextBreakdownを確認済み。前者は累積カウンタ、pressureはプロバイダ入力に基づく値と推定、breakdownは既存の固定ヒューリスティックであり、新パネルで実測として扱わない。必要なネイティブコンテキスト情報は共通のセッション投影へ供給し、画面に計算処理を分散させない。

## レイアウト候補

Aは既存popoverの常設化のみ。Bは既存ui-sidebar-rightのDockLayout外側へ固定summary slotを追加し、共通使用量データを接続する。Cは右パネル全体の再構築。今回の推奨はBであり、既存のファイル・ターミナル・分割・幅調整・会話別保持を活用する。狭い幅では既存fullscreen方針を維持し、通常幅での常時表示を優先する。

## 確認範囲

既存コードと公式ドキュメント、インストール済みSDK型を調査した。アプリ変更・自動テスト・型検査・推論は実行していない。2026-10-17のCodex風UI指定を反映し、B案で実装を進める。

## 概要カードと詳細サイドバーの分離

利用者の2026-10-17の訂正を反映する。右上の小さいカードは指標を短く表示し、クリックで対応する詳細タブを開く。詳細サイドバーを開いている間はカードを隠す。右上の既存ボタンからも詳細サイドバーを開ける。概要用の幅300pxと詳細の可変幅を分離し、概要表示で詳細を自動展開しない。

## チャット内配置への訂正

概要カードはframeのrightbar列ではなく、mainのconversation.content内へ登録する。メインヘッダーは右端まで全幅に戻す。概要と会話は同じscrollBodyに入り、スクロールバーは領域全体の右端に置く。カードはチャット内の右上でstickyとし、詳細サイドバーを開いたときだけ非表示にする。外側レイアウトに概要専用の幅・状態は追加しない。

## 中央軸

本文と入力欄は左サイドバーを除いたメイン領域全体の中央に揃える。概要カードの幅を引いた残りの中央にはしない。標準の本文幅は744pxとし、概要が表示される幅では左右対称に余白を確保する。左サイドバーの初期幅は340px、概要は右端から16pxに配置する。

## モニターとノートPCの参考画像

追加の2枚を受け、常時全体中央で縮小する方針を改める。主領域1400px以上は全体中央、1000〜1399pxは右カード用300pxを確保した残りの中央に本文と入力欄を配置する。1000px未満は概要を隠す。これは参考画像の挙動に合わせた実装上の閾値であり、Codex内部の閾値を確認したものではない。
