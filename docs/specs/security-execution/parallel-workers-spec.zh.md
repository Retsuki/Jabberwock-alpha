# 并行 Worker

[English](parallel-workers-spec.md) | 中文

## 概要

> 独立调查使用滚动池，保留共享 HTTP 额度、独立控制和重启后不自动执行的要求。可选持久化字段兼容旧历史。

## 用户流程

按配置的并发数派发 Worker。每个 Worker 有独立对话、活动提示、指令和审批。出现空位便领取下一项，其他 Worker 继续运行。单独停止只影响选中 Worker；调查停止等待全部所属 Worker 结束。现有 Planner 审查使用已结束结果。重要发现或失败阻止后续派发，等待当前操作结束。

## 额度与持久化

`executionMaxConcurrentWorkers` 默认为 3，保存到可选 `snapshot.limits.maxConcurrentWorkers`。旧记录缺失时解析为 1。并发数不超过待办数和可用 HTTP 次数。`dispatches` 在准入前持久化请求标识、目标与额度。已结束操作的实际消耗加未结束预留不超过全局上限。只有 Worker 操作及清理结束后才归还未用额度。

仅协调器可调用 `startReserved`，必须匹配当前执行的预留。手动启动不能绕过运行中的全局额度。相同请求标识不能用于不同输入。准入按任务串行，运行按 Worker 标识隔离。

## 停止与重启

任务取消阻止准入，终止所有所属 Worker 并等待清理。范围变更和超时使用相同机制。重启将未结束记录标为中断，不回放预留。显式继续保留实际消耗和成功审查，创建新预留。旧版严格读取器在执行前拒绝未知字段。

## 验证

受控测试覆盖并发、空位补充、额度、清理后额度归还、消息审批隔离、取消、存储失败与重启不自动运行，无需外部调查。
