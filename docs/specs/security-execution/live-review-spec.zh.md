# 调查期间的 Planner 审查

[English](live-review-spec.md) | 中文

## 概要

> 不等待整个池即可审查已结束的 Worker 结果。复用现有界面与工具权限。可选领域字段保留旧历史，不修改 Session 格式。

## 用户流程

用户正常启动已保存任务。Worker 结束后，Planner 审查其已保存结果，其他 Worker 继续运行。历史显示每次决策使用的结果。继续决策可新增调查或明确停止过时的活动调查。仅等待的继续决策要求仍有捕获的 Worker 运行。终局决策先停止并等待剩余工作，再公布结果。

## 协调

一个协调器管理待办、活动运行和 HTTP 预留。待审查的已结束结果与活动操作分开。审查捕获属于此执行的不同计划代际的终态结果标识，以及活动 Worker 的只读快照。成功审查仅确认捕获的已结束结果；推理期间到达的结果触发下一次审查。失败或取消不确认结果。Planner 调用和请求额度保持有限。

最新继续计划只替换待办。运行中的语义目标与已确认覆盖阻止重复派发。可选 `stopWorkerRunIds` 只能包含此次执行快照捕获的活动标识，省略时不停止单个 Worker。取消前已结束的结果保留，取消目标仍未确认。没有新项目的继续决策要求至少一个捕获的活动 Worker 不在同次停止名单中。

可选执行字段 `reviews` 在调用前持久化审查请求标识、前序计划、捕获的 Worker 标识、结果计划及应用状态。Planner 按执行所属派发验证此记录。新快照保存明确的 Worker、计划与项目引用，旧手动审查保持同计划规则。中断前已完成但尚未应用的决策只在明确继续后应用；停止和准入标识保持幂等。

## 额度与历史

快照区分已消耗 HTTP 次数、未结束预留与未预留额度。开始审查不释放预留。准入重新校验当前任务和总额度。旧计划没有停止字段时不停止单个 Worker。重启不自动恢复。明确继续保留实际消耗和成功审查，从已结束但未审查结果恢复，不重复目标请求。

审查输出示例：`{"decision":"continue","summary":"Keep the active check and inspect the new lead","items":[],"stopWorkerRunIds":[]}`。仅在有捕获的活动调查时允许此等待输出，普通手动审查仍要求继续项目非空。

## 验证

受控测试覆盖慢 Worker 结束前审查、审查串行、推理期间结果不丢失、停止校验、预留保持、不重复目标、终局清理和重启兼容。原生界面复用任务历史。真实模型本地测试仅使用现有虚构环回应用与保存的权限。
