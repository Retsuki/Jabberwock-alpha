## 源码安装验证

无 Git 导出目录使用独立的 pnpm 11.28.5、空 npm 配置，且不含原目录的 `node_modules`，在 8.9 秒内成功安装了 366 个工作区。安装使用 `--offline --frozen-lockfile` 和现有包缓存；完整的全新网络下载尚未验证。原生编译成功，七项产物构建检查全部通过，Host 和 Client 汇总检查均通过且零失败。

三个初始环境错误通过现有机制解决：以独立的固定版本 pnpm 可执行文件替代全局 Volta pnpm shim；将不匹配的编译器/链接器和 SDK 选择修正为同一 Xcode 工具链；无 Git 导出目录通过 `DSH_CLIENT_COMMIT_HASH` 提供实际源码的 Git 修订号，供客户端构建元数据使用。未禁用产品检查来获得这些结果。

随附的 Web 配置使用隔离的 HOME 和 DSH_HOME 目录启动。带所有者 cookie 的 HTML 请求返回 HTTP 200，共 37,651 字节，启动引导重定向到干净 URL，关闭后监听端口已关闭。支持的 `start:desktop` 启动器也使用独立端口、隔离的允许列表环境、HOME、DSH_HOME 和用户数据目录打开了实际 Electron 窗口。实画面检查显示默认 Workspace 和“No model selected”；点击 Settings → Models 后显示 Codex 未登录，Claude 官方客户端不可用。DeepSeek API 环境变量不存在。这验证的是干净启动和未认证模型状态展示，不是认证或外部推理成功。正常 `app.quit` 以代码 0 退出，三个专用 Desktop 调试/Host 端口全部关闭。未改动原先运行的普通应用。

实际首次启动和 Models 截图已目视检查，Models 画面已通过 `verify.py ui` 登记。截图及机器专属日志因包含个人路径而保留在源码分发范围之外。这些检查验证了该导出 macOS 候选目录在已有包缓存条件下的安装、构建和启动，不证明 Windows/Linux 启动、完整全新下载或未来远程克隆的内容。将当前 16,768 个文件的候选目录与已测试导出目录进行 SHA-256 比较，差异仅为六个 README/验证文档文件；实现和测试文件一致。最终公开候选版本仍需重新检查文件清单和 Git 历史。
