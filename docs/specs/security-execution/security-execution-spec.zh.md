# 安全执行规格

[English](security-execution-spec.md) | 中文

> 10 秒摘要：独立安全服务共用已保存任务、任务会话、Planner 提案及有界 Worker 执行。所有者从登记资产与范围规则启动调查，无需输入 URL。Planner 选择支持的匿名 GET 操作，复核 Worker 证据并决定继续、完成或请求输入。已有任务记录及精确目标执行历史仍可读取。

## 范围与批准

用户已批准方案 B 和先实现会话的交付顺序。已注册工作区的所有者打开已保存任务，选择 Sessions，发送消息并收到主 Agent 回复。会话读取已保存的描述、目标、资产和规则，记录模型实际收到的上下文，并在重启后仍可访问。未保存或保存失败的任务编辑必须在发送前完成保存。空输入、重复提交、认证不可用、提供方错误和取消均有明确显示；失败轮次不得显示为成功回复。

首个通道使用现有 Claude 订阅并禁用原生工具。它不引入 API 凭据，也不改变普通聊天权限。在适配器能执行同样限制之前，Codex 不提供此仅会话能力。仅靠模型指令不能约束工具。任务会话与普通主聊天及任务草稿聚合分别拥有；调用方不能选择其他任务的会话标识。

## Planner 与调查队列

所有者在任务 Sessions 中明确要求主 Agent 启动 Planner。完整结构化响应可同时请求 Planner 并提交设置提案。Host 先保存有效提案，不再询问下一项设置，并按已保存版本启动规划。Host 要求五项设置检查通过、自动保存完成且任务版本未变。Session、轮次和步骤确定幂等请求；交接失败明确显示并支持重试。设置变更须在 Planner 准入前完成保存。客户端须先保存任务待修改内容。独立规划服务将已保存任务配置、所选资产、记录版本和主 Agent 会话引用捕获为不可变输入快照。它单独拥有规划 Session 和计划记录，不放入任务草稿聚合或普通会话 Session。规划不代表批准诊断执行。

Planner 使用现有禁用原生工具的 Claude 仅会话通道。完整提示记录在其 Session 中。只有明确完成的轮次才能提供最终计划；无效 JSON、不支持字段、未知资产引用，以及失败或部分响应均不得生成队列项目。Host 分配项目标识和待执行状态。项目说明目标、目的和拟议方法；规划不会自动派发 Worker。

每个任务最多一个活跃计划生成，重试使用稳定请求标识。服务持久记录生成、完成、取消、失败和重启中断。已取消或已中断计划不能被迟到模型响应改为就绪。重启保留完成计划和待执行项目，不自动恢复未完成模型请求。读取、生成和取消均校验工作区所有权与任务身份；删除或归档任务会取消活跃生成。

Sessions 显示 Planner 结果，任务总览展示同一已保存计划。界面区分生成中、就绪但未执行、失败、已取消、已中断和空结果。修改任务不会改变已保存快照；任务或所选资产配置变化时，界面指出计划已过时。仅修改其他工作区内容不会令计划过时。Planner 面板依据已记录尝试状态、时间戳、快照及待执行项目显示操作历史。不展示私有推理，不虚构 Worker 分配或结果。刷新重新读取已保存状态，取消停止当前规划。不提供独立创建计划按钮；检查清单完成本身不会启动规划。

## 任务设置会话提案

用户已批准本阶段的引导设置。创建只需任务名称和至少一项已注册资产，随后打开 Sessions 并选择主 Agent。创建操作说明会将所选任务上下文发送至现有 Claude 订阅以开始设置。先保存任务，再调用模型；失败时保留草稿并提供幂等重试。打开旧任务不会自动调用模型。

主 Agent 每次只询问一项缺失信息：目标与完成标准、明确的目标范围、所有者的诊断许可、允许/禁止操作与排除项、执行上限与停止条件。使用当前保存值及已接受回答，不重复询问已完成事项。含糊讨论不视为确定。明确回答产生完整且验证通过的变更后自动保存，并继续下一个问题，不再要求逐项点击接受。界面也可直接编辑同一权威任务字段。

使用独立安全设置服务及内部结构化会话引擎。复用现有 Claude 禁用工具通道，收集完整响应，严格验证回复/提案对象，只将验证后的自然语言回复发布到会话。准确原始响应和已接受输入持久记录，不将控制 JSON 显示为聊天文本。引擎集成不得放宽原生工具限制或增加目标访问。普通聊天、Planner 生成和 Worker 执行仍各自负责。

设置在每次尝试时，通过 `EngineRunRequest.responseSchema` 提供已在任务上下文提示中记录的同一 JSON Schema。Claude 纯会话使用 SDK `outputFormat:json_schema`，只接受符合 schema 的 `structured_output`；成功却缺失该字段、输出无效或 SDK 结构化输出错误时均失败，不回退到普通文字或持久化提案。只有请求 schema 时才可出现精确内部载体 `StructuredOutput`，其权限输入也必须通过该 schema 验证；原生工具、代理、技能、插件及 MCP 仍禁用。其他引擎保留现有文本输出及严格设置解析。主聊天与 host-tools 路由不变，也不能使用此 schema 路径。

保存任务的设置元数据为可选字段，使旧任务和不可变规划快照仍可读取。Host 根据已接受设置与当前任务推导五项检查状态，不信任模型提供的勾选。范围和许可确认绑定所选资产；重要配置变更使受影响确认失效。全部完成表示可交接规划，不代表获准执行诊断。所有者通过主 Agent 明确请求 Planner；不包含 Worker 执行。

只有已注册工作区所有者可开始、读取或确认设置。模型不能任意选择任务身份、版本、时间、批准状态或运行状态。接受提案使用当前预期记录版本；直接编辑冲突时拒绝应用，保留已保存设置及可见提案供复核。部分、失败、取消或中断的推理不能应用提案。重复开始/确认请求不产生重复轮次或写入。重启保留已接受回答及未完成检查项，不静默恢复推理。

开始请求与响应示例：

```json
{"workspaceId":"workspace-id","taskId":"task-id","requestId":"stable-request-id","locale":"ja"}
```

```json
{"sessionId":"security-session-id","accepted":true}
```

## 有界执行

流程为资产登记、任务草稿、结构化计划预览、所有者明确批准、一次有界请求以及任务详情结果展示。首个操作为一次匿名 GET；仅当执行器明确支持并验证方法时才考虑 HEAD。任意 shell、攻击载荷、多 Worker 协调、身份认证与新增 API key 集成均不在范围内。

## 运行时所有权

`securityWorkers` 服务拥有独立存储域和运行记录，不得将实时执行状态存入 `securityRecords` 草稿聚合。不可变运行快照包含任务配置版本、范围、编译后的操作、限制与所有者批准的计划。仅已注册工作区的已认证所有者可创建、批准、启动、查看或停止其运行；每个任务最多一个活跃运行。

生命周期持久记录准备、批准、启动、停止、完成、失败与中断。重启将未结束运行标记为中断，不自动恢复请求。迟到的请求结果不得覆盖已停止或已中断的终态。停止会中止请求与正文读取，并通过条件终态写入防止完成竞态。

## 范围与传输

将域名、IP、CIDR 与 URL 范围规则编译为明确允许的操作，拒绝规则优先。请求主机名与每个候选解析地址均须通过已批准范围及公网地址策略。自由文本约束并非已机械执行的规则：不支持或含糊的规则须阻止执行，改为要求结构化且人工批准的计划。草稿编辑不得改变运行中的计划。

复用 `packages/web/web-fetch-http/src/network.ts` 的公网地址验证与固定 DNS 连接，不得以仅检查 URL 替代。提供者内部须拒绝经过代理的请求，因为现有代理路径将 DNS 委托给代理，无法证明固定地址策略。配置为不跟随重定向、限制请求/响应字节，并设置明确有限超时。不发送 Cookie、Authorization 请求头、浏览器会话或模型凭据。DNS 重绑定、非公网地址、不支持的协议与未解决的策略判断均须拒绝。

## AI 规划边界

`packages/core/subscription-engines/src/codex.ts` 与 `claude.ts` 中的现有原生适配器拥有引擎工具和权限，不是已证明受约束的诊断执行器。连接任一适配器前，须依据当前官方契约与现有代码证明规划已禁用原生工具，或只能通过强制已批准计划的 Host broker 操作。拒绝未证实路径。安全、人工批准的结构化计划可以验证执行器，但不得声称 Planner/Worker 自主执行已经实现。

主审已查看官方 [Codex App Server 契约](https://learn.chatgpt.com/docs/app-server)：动态工具为实验功能，需启用实验 API；以及 [Claude SDK 权限](https://code.claude.com/docs/en/agent-sdk/permissions)：自动批准工具可跳过 `canUseTool`，需以 `PreToolUse` 作为拦截边界。现有原生提示组装不将完整系统指令作为强制机制转发。这些事实要求分别证明适配器边界，并不表示拟议规划边界已有效。

## UI 与验收

任务详情须区分已保存配置、不可变获批计划、实际运行状态和观察证据。仅显示执行器记录的事件及结果，不得将示例发现升级为真实漏洞，也不得在编译成功前把登记范围称为已执行控制。

验收覆盖范围拒绝、固定地址检查、代理拒绝、零重定向、字节/时限、所有者隔离、单活跃运行准入、停止竞态与重启中断。重点策略、生命周期测试和固定模型与传输的组合 UI 执行已通过；真实 Worker 模型应答与远程身份隔离仍未验证。参见[实施计划](security-execution-implementation-plan.zh.md)。

## 主 Agent 模型选择

所有者在主 Agent 标题栏选择引擎和原生公布的模型。任务会话映射持久保存选择，旧数据兼容 Claude/default。只允许在 Session 空闲时更改，保留会话及草稿，并从下一轮（包括引导设置）生效。Host 拒绝不支持的引擎和未知模型；切换模型不会扩大执行权限。列表获取失败明确显示，不自动更改选择。Planner 和 Worker 遵循下方角色模型策略。

## Worker 执行与角色模型

概览与会话偏好共用 `task.agentModels`；`task.agentModelModes` 让 Planner 和 Worker 在未明确固定时自动选择。自动模式下，主 Agent 选择 Planner 模型，Planner 为每项选择 Worker 模型，Host 验证实际目录 ID 和简短理由。所有者的固定偏好优先于自动决策。缺少模式时，旧明确模型保留为固定，未设置或默认模型按自动处理。每次新调用记录解析后的模型和理由，后续编辑不影响正在运行的 Agent。缺少项目模型决策的旧计划仍可读取，但自动执行 Worker 前须重新规划。主 Agent 标题栏保留现有任务专属选择行为。

`securityWorkers.start` 接受所有者明确批准的操作：`{workspaceId,taskId,planId,itemId,assetId,url,requestId,expectedRevision}`。Host 在访问目标前验证当前保存配置、已完成计划、设置清单、登记资产、拒绝优先的范围及准确 GET 操作。无法编译的自然语言限制拒绝执行。`read` 仅投影保存记录；`cancel` 停止活动尝试。独立存储域保留不可变输入、所选模型、时间、实际 HTTP 证据及模型摘要。重复请求返回已接收的运行；取消和重启不能被延迟成功覆盖。模型整理禁用所有原生工具；响应正文作为不可信引用数据，不作为指令。

首个 Worker 不跟随重定向、不发送凭据、拒绝代理与非公共地址，连接固定到已验证 DNS 地址，并限制请求时间、响应字节和模型耗时。结果描述观测，不宣称漏洞已确认。其他操作和并发 Worker 仍不可用。明确启动的执行可以派发已授权的结构化 GET 操作，并将观察结果交回 Planner。

## Planner 与 Worker 执行循环

所有者基于就绪计划与当前保存版本启动任务执行，无需输入 URL。执行服务在派发前捕获 `targetMode: asset-scope`、所选登记资产、任务范围规则以及有限轮数、请求数和总时间。Planner 选择 HTTP(S) 路径及登记根域下允许的子域，生成支持的结构化匿名 GET 操作，接收权威 Worker 终态观察并选择继续、完成或需要输入。Host 按捕获的资产范围及拒绝优先规则校验每个操作；Worker 在固定连接前重新检查每个 DNS 候选地址。不支持的调查需要所有者输入，不能记作已确认发现。没有此模式的旧执行保持精确授权资产/URL 限制，绝不静默扩大或恢复。

每轮保存指令计划、Worker 运行标识和 Planner 决策。请求通过已有策略检查执行器顺序执行；重复操作不能形成无休止调查。停止会取消活动工作并等待结束。重启将未完成执行记为中断，不自动恢复网络流量。任务设置变化停止后续派发。完成只表示授权的有限观察流程结束，不证明资产无漏洞，也不生成渗透测试报告。

## 主 Agent 委托和会话导航

当前所有者请求执行或委托调查时生成结构化 `start-investigation` 动作，与仅规划的 `start-planner` 区分。完成输出并校验当前准备状态后才能准入，同轮修改先保存。自动 Planner 选择提供真实目录模型及理由。执行协调器管理初始规划、子任务停止和后续复核；旧计划缺少模型元数据不会触发未选择的默认模型或无控制派发。稳定动作标识对重复完成通知去重。

Sessions 侧栏在 Worker 标题下逐项列出实际运行。状态更新或新增 Worker 不改变已选运行。Planner 按时间显示轮次分隔和可展开的指令/报告行，并提供停止和失败反馈。标题固定，侧栏及活动内容各自滚动。

## DeepSeek 角色模型

主 Agent、Planner 与 Worker 选择现有 DeepSeek 账户及 API 提供方公布的模型。路由保留独立认证与目录；不可用选项会报错，不会静默更换提供方或模型。无工具适配器使用已记录的讨论输入，保留取消与任务隔离。切换提供方保留可见会话；共享以往讨论需要对该 Session 与目标明确授权。现有 Claude/Codex 选择仍可读取。新选择作用于后续调用，也包括角色自动决策；HTTP 范围执行与所选模型独立。

## Worker 会话与执行日志

选择实际 Worker 会打开按时间排列的会话：捕获的 Planner 指令、公共 HTTP 请求结果、Worker 报告、关联的 Planner 复核及所有者追加消息。只有已就绪保存计划的 Worker 运行引用包含该运行时，才显示其实际复核摘要；由计划派生的稳定条目标识防止重复。请求详情和已保存证据可就地展开，不展示模型私有推理或虚构工具活动。运行中与已完成 Worker 使用同一视图，标题/输入框固定，会话独立滚动。重新打开及重启后保留已保存历史。

追加消息属于准确的任务及 Worker 运行，使用捕获的模型，对捕获的任务上下文和现有证据进行无工具分析；不会发出另一个 HTTP 请求、重启调查或执行文字中的命令。准入检查所有权及任务可用性，通过稳定请求标识去重重试。初始 Worker 运行时可排队一条所有者指令，初始操作结束后开始分析。活动或排队的追加消息阻止再次提交。会话状态独立于原始执行结果。取消和重启保留历史，不会将未完成回复变为成功报告。新调查操作仍由 Planner 负责。

## 已记录活动视图

时间线与探索共享具有稳定实体标识的任务计划、Worker 和执行投影。时间线展示持久时间、来源、状态、关联记录与载荷。搜索、类别筛选和排序不修改存储。自动刷新可暂停；重叠或旧任务读取不能替换当前任务数据。探索区分目标范围上下文和已记录派生关系。缺失观察和中断尝试保持可见，不伪造发现或目标达成。视图不启动推理或目标通信。

## 发现与复测流程

Worker 将有证据支持的结构化发现与叙述摘要分别登记；怀疑及普通观测不会成为已确认漏洞。每条发现归属于工作区和任务，引用来源 Worker 与资产，并保留原始 HTTP 证据。严重程度和用户处置与复测执行、结论分别管理。旧 Worker 历史仍可读取，不虚构发现。

用户选择发现，可补充修复版本或测试条件，并发起针对性复测。服务捕获原始发现和当前任务限制，在执行前保存受理记录，使用与 Worker 相同的公网 DNS 固定匿名 GET 策略及有限执行上限。复测具有独立会话、新证据及不可变的终态历史；重复启动复用进行中的尝试。结论为 reproduced、fixed 和 inconclusive。目标不可达、不支持的操作、证据不完整或缺少可比条件不能推断已修复。只有 completed 且 fixed 才自动更新处置；原证据不变。取消、重启及任务移除会停止工作，不自动恢复。

两个标签展示真实保存数据，刷新时保留选中记录，明确显示读取及操作错误，并在可滚动详情中容纳长证据。复测历史展示执行状态、结论、补充说明、时间及证据；任务标题和标签保持在滚动区域外。

## 响应捕获存储与报告

新操作保留有限响应文件，与发送模型的有限文本分别管理。模型可见摘录标明字节窗口，并记录在会话中。捕获截断产生部分获取，不作为大小上限失败；网络、存储、策略与期限失败仍为失败。旧内联证据保持可读。完整获取不代表完整模型分析，不完整获取或分析均不能将复测关闭为已修复。

Planner 复核接收权威操作覆盖信息。仍有失败、部分检查、未执行或不支持工作时，完成提议变为 needs-input，不接受未经验证的目标完成声明。报告标签读取最新执行快照及保存证据、发现与复测，不请求新模型或 HTTP，保留缺口并提供一致的 Markdown。计数表示计划操作，而非唯一 HTTP 请求。零发现区别于完整测试，绝不证明整个资产安全。

## Planner 与 Worker 的令牌标题栏

保存任务的 Sessions 在 Planner 与 Worker 标题栏右侧显示输入、缓存读取与输出令牌数。Planner 汇总任务内每个独立保存的 Planner 会话。Worker 仅显示自身会话，包括所有者追加消息的回复。提示保留缓存写入计数及精确数值。紧凑计数不表示货币费用。

客户端读取现有提供方报告的会话用量，不启动 Agent、不发送模型输入，也不访问诊断目标。原生累计快照替换先前快照，不重复相加；API 模型总量使用现有令牌投影。缺失测量显示破折号，报告的零保持为零，缺失会话不会静默变成完整汇总。刷新及任务/Worker 切换保留来源标识并丢弃过期读取。不新增计量存储或持久化模式。

## 资产覆盖

覆盖页展示已保存的公司、域名、子域名、IP、服务、应用和端点关系。符合任务范围的已登记资产构成分母；匹配本任务的真实 HTTP 观测将资产计为已观测一次，包括部分观测或后续模型失败。仅有计划不计为已观测。公司和上下文连接节点不计入统计。排除规则优先，未确定范围明确提示，分母为空或不确定时不显示百分比。触达程度不代表诊断完成。查看本页不执行 DNS 查询、资产登记、模型调用或目标访问。

关系图支持搜索、类型和观测状态筛选、分组折叠与逐步展开、节点拖动、双指平移、以指针为中心的捏合缩放及适应视图。详情面板保留固定标题与独立滚动的已保存引用、有限长度的证据预览，并可跳转到对应 Worker 会话。刷新保留实体标识并丢弃过期响应；失败时保留已有数据并明确提供重试状态。

## Planner 响应恢复与显式继续

Planner 每种模式仅使用一种输出约定。完整响应若未通过 JSON 语法或结构校验，会在同一无工具 Session 内收到有限次数的纠正请求；每次请求和响应都保留日志。总响应次数默认两次，最多三次。资产、模型和操作策略拒绝、存储失败、取消及超时不属于格式重试条件。原计划超时限制覆盖全部纠正尝试。禁止截取子串或拼接 JSON 将无效输出变为可执行项目。

主 Agent 标题栏提供显式继续最近失败、取消或中断调查的操作。继续使用新的请求和执行标识，保留原执行记录不变并记录其来源标识。任务修订、操作设置、登记资产和目标授权必须仍然匹配。已完成及失败的 Worker 结果直接提交复核，不再次访问目标；中断或取消的工作仍属未确认，可重新派发。请求数及成功复核轮次预算继续累计；用户明确继续时获得新的用时窗口。重启不会自动恢复调查。拒绝或结果未确认的继续请求会明确显示，并以稳定请求标识提供重试。报告保留引用观测，并区分完成与未解决工作。

Worker 在一次 HTTP 获取后采用同样的有限结果格式恢复规则。JSON 报告格式错误时，在同一 Session 内使用保留证据请求另一次响应，不重复访问目标。`workerResponseAttempts` 默认为两次，最多三次；全部响应共享现有模型截止时间。证据引文拒绝不属于格式重试。旧 Worker 快照保持可读，历史失败记录不会被改写为完成。

## 本地漏洞验证

经所有者授权的本地合成应用通过真实任务界面、Planner、Worker HTTP 传输和发现导入进行调查。本地 HTTP 需要显式精确来源主机配置；普通部署仍仅允许公网。本地模式仅允许配置端口的规范 IPv4 环回，保留登记服务／端点及排除优先范围校验，不能由模型指令扩大权限。发现必须来自实际匿名 HTTP 证据及其引文；fixture 事实或预期发现不会直接写入任务存储。应用仅使用合成记录，不监听外部接口。


## 管理层报告呈现

> 已保存任务报告以现有 UI 基础组件和主题令牌呈现八个连续章节。仅改变只读展示，不修改持久化、模型请求或执行行为。

报告纵向依次展示执行摘要、风险概览、前五项发现、记录的业务影响、有证据支持的风险场景、建议修复优先级、范围与限制及结论。章节内部卡片可并排，但八个章节不分为报纸式多栏。窄屏表格局部滚动。完整 Markdown 导出及可展开技术证据仍可访问。

纯投影从规范报告计算活跃严重性数量、受影响的已登记资产、按原始标题分组及修复优先级。误报和重复项不计入发现；已修复保留历史但不计入活跃风险；已接受风险仍为活跃。综合风险指最高活跃保存严重性，不是独立审计评级。没有活跃发现不代表安全。发现统计涵盖任务历史，操作覆盖使用最近执行快照，分别标明。

影响与场景复用已保存发现摘要及引用证据，标为记录的 AI 评估而非已确认业务损失。响应优先级按严重性计算，不虚构截止日、损失、上次比较、机构详情或不存在的分类。读取报告不新增 AI 生成。空数据、未开始、进行中及未完成调查均保留覆盖范围说明。
