# 主聊天安全控制

[English](main-chat-control-spec.md) | 中文

## 摘要

> 已批准的设计：所有者可以在普通主聊天中管理工作区安全任务，并打开同一任务的界面。公共操作服务委托现有的记录、设置、执行和 Worker 服务。现有的任务权限、修订和预算检查仍具有决定权。预计不改变持久化格式；需要验证的主要风险是跨工作区访问和选择错误任务。

## 所有者流程

所有者询问主聊天有哪些安全任务，或某个任务的进展。代理读取当前工作区，并展示任务名称、标识符、状态和发现事项。如果多个任务符合请求，代理必须先询问所有者指的是哪一个，再进行修改。

所有者可以使用名称和已登记资产创建任务，讨论设置，并要求开始调查。缺失的检查项保持可见，现有准入检查会阻止执行。成功修改的设置立即可在任务概览中读取；打开返回的任务链接会选择该任务界面。

所有者可以停止或恢复任务，并向选定的 Worker 发送补充指示。指示被接受不代表新调查已完成。现有的 Worker 讨论和 Planner 执行负责人决定哪些操作可以运行，哪些需要重新规划。

## 操作

绑定工作区的操作负责人支持列出任务和资产、读取任务详情、执行状态和发现事项、创建任务和修改配置、开始／取消／恢复执行、发送 Worker 指示和任务导航。它复用现有服务方法，不引入第二套执行控制器。主聊天工具提供模型可读的说明和有界结果；请求被拒绝时明确报告，不虚构成功状态。

`security_control` 工具接受不含模型自选工作区身份的命令，并返回有界结果：

```json
{"command":{"action":"read","taskId":"task-example"}}
```

```json
{"action":"read","workspaceId":"workspace-example","taskId":"task-example","data":"{\"revision\":1,\"task\":{\"name\":\"Local verification\"}}"}
```

配置修改基于最新保存的修订。并发编辑返回冲突，需要重新读取；适配器不会悄悄覆盖整个过期工作区快照。任务和资产标识符必须属于调用者的工作区。模型不能选择其他工作区来获取访问权限。

## 责任与限制

`src/security-control.ts` 负责解析工作区、验证请求和委托；`src/control-types.ts` 定义协议，`src/security-chat-tools.ts` 适配普通聊天工具。记录存储负责持久化设置；设置服务负责检查清单评估；执行服务负责启动、取消、恢复和预算；Worker 负责自己的会话记录和指示。普通聊天和任务界面观察同一组负责人。

只有所有者的普通工作区聊天获得这些工具。安全内部 Session 不会获得递归控制任务或无关会话的能力。模型可见的工具输入和输出保留在调用 Session 的常规工具历史中。现有的提供商同意、凭据和操作授权继续生效。原生 Claude 主机工具和 DeepSeek 使用的 Harness 工具路由提供该命令；Codex 没有兼容桥接，无法执行这些控制。

浏览器调查、任意外部工具执行、删除任务数据和扩大凭据不属于本功能。测试使用虚构的本地任务，不调查外部目标。

## 验收

定向测试覆盖工作区隔离、任务不存在、选择歧义、过期修订冲突、检查清单拒绝、取消、恢复、Worker 指示委托和导航。原生应用测试通过普通主聊天发送请求，并验证对应任务界面和保存的服务状态。截图和测试输出证明观察到的行为；本设计文档不声称实现或验证已经完成。
