# 本地 EC 安全基准

[English](ec-lab-spec.md) | 中文

> 构建一个仅本地运行的脆弱 Next.js EC 应用，包含虚构顾客、商品、订单及管理区。它是独立于 Jabberwock 的诊断目标；不包含修复版本、真实支付、外部身份服务或产品数据迁移。

## 所有者流程

所有者打开商店、浏览商品、登录、加入购物车并提交模拟订单。另一位顾客和管理员提供不同授权上下文。Jabberwock 随后仅使用提供的测试凭据调查已登记本地服务；不向诊断模型提供评估答案。发现必须来自实际观测，后续再依报告修复并复测。

## 应用

`benchmarks/security-labs/northline/app` 拥有独立依赖锁、服务器和数据目录。Next.js 14.2.24 固定为刻意选择的旧框架版本，处于[官方中间件公告](https://github.com/vercel/next.js/security/advisories/GHSA-f82v-jwr5-mffw)影响范围。版本匹配只说明暴露可能，不证明影响已实现。服务器仅绑定 IPv4 环回并拒绝其他 Host 值。不降级产品依赖。

应用包括商品搜索分类、商品详情、浏览器持久购物车、登录/退出、账户编辑、结账、订单列表/详情及管理员订单/顾客视图。虚构状态存于应用忽略的 `.data` 目录。登录会话使用带签名和过期时间的 HttpOnly Cookie；启动进程提供新私密签名密钥。没有公开端点返回评估答案或重置状态。

## 评估

应用服务目录之外的仅操作员清单记录预期案例、正常对照和夹具重置方法。功能冒烟测试验证正常购物和预期基准行为，但不将其计为 Jabberwock 的发现。首次交付仅包含脆弱应用。根据报告修复、清洁复测及重复模型对比属于后续工作。
