# 订阅引擎历史共享设置

[English](history-sharing-spec.md) | 中文

> 用户可在 Models 设置中分别选择 Claude 和 Codex 的对话历史共享方式。当前配置档保存选择；已有配置档保留确认行为。不改变数据库或 Session 格式。允许共享可能会发送用户或助手消息中已有的机密文本。

## 用户流程

1. 打开 Models 设置，找到 Claude 和 Codex 订阅连接。
2. 为每个提供方选择 `ask`（正常的对话级确认）或 `allow`（不再询问直接共享）。在用户更改选择前，说明列出发送目标和共享内容。
3. 通过现有设置流程保存。当前配置档在新对话和重启后保留选择。
4. 新原生对话需要已有历史时，`allow` 对该提供方省略共享提问。`ask` 使用现有的本次允许／此对话始终允许／拒绝选项。
5. 恢复 `ask` 会恢复该确认机制；已记录的此对话与提供方许可仍然有效。不会撤销或删除该许可。

## 内容与默认值

省略配置代表 `ask`。Claude 和 Codex 的选择互相独立。历史只包含以往用户与助手的文本：不导入系统指令、工具结果或凭据文件。文本中的机密信息仍属于共享内容。没有历史的轮次以及恢复同一个原生提供方对话时，保留现有的不提问行为。

此策略适用于使用公共提示构建器的订阅原生入口，包括对话和 Host 工具变体。DeepSeek 共享不在本次变更范围。此设置仅授予历史共享，不授予工具执行、目标访问或诊断权限。

针对虚构诊断测试的一次性授权不会启用该应用设置。只有用户明确选择 `allow` 才启用无需确认的共享。

## 配置与归属

现有订阅引擎配置负责可选的 `historySharing.claude` 和 `historySharing.codex`，各自取值为 `ask` 或 `allow`。这些字段是 volatile 配置，因此后续轮次能读取实时设置变更。现有配置表单、`remote.settings.mutate`、修订号及 Gateway/settings 访问控制将变更保存到当前配置档的 `cordis.patch.yml`；不引入并行偏好存储或新的 Remote 端点。

插件配置示例：

```json
{"historySharing":{"claude":"allow","codex":"ask"}}
```

现有设置修改操作返回正常的成功设置视图或冲突／拒绝；UI 会报告保存失败，不会将请求中的策略显示为已保存。公共原生提示构建器明确接收已解析的提供方策略。现有对话许可投影和历史过滤仍然是权威机制。

## 设计决定

已批准 B：复用现有设置持久化，并在公共提示构建器中集中判断策略。A 为每个引擎增加独立确认分支，会重复行为。C 重建许可管理，在没有新存储需求时扩大范围。本功能无需新存储系统或独立许可服务。

## 验收

- 聚焦测试覆盖默认值、提供方隔离、明确允许、恢复询问及已有对话许可。
- 保存、重新加载与重启后保留配置档选择；过期修订号和被拒绝的修改仍为错误。
- 测试保留无历史和原生恢复行为，并证明不会将系统／工具／凭据文件内容加入共享历史。
- 在实际应用中检查设置，但不会用仅限测试的授权启用全局允许。外部模型测试需取得针对实际数据和发送目标的授权。
