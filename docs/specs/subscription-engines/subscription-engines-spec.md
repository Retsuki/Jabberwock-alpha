# サブスク実行エンジン仕様

> 10秒サマリー: Jabberwockの利用者が、メインチャットをCodexまたはClaude Codeの契約枠で動かす。既存の会話・画面・キャンセルを維持し、実行エンジンと接続状態を選択できる。APIキーへの自動切替はしない。DBスキーマは変更せず、ネイティブ会話との対応をセッションイベントに記録する。公式CLIのログインと利用上限に依存する。

## ユーザーフロー

1. ログインなしでメイン画面を開く。
2. 設定のModelsでCodexとClaudeの接続状態を確認する。未導入の場合は導入が必要なことを表示する。
3. Connectから各公式ツールの認証を開始する。認証操作は利用者本人が行う。Refreshで接続状態を再取得する。
4. 既存のモデル選択欄からCodexまたはClaudeのサブスク実行を選び、メッセージを送る。
5. 応答を逐次表示し、必要な操作許可は既存の質問UIで確認する。拒否・キャンセル時に権限を自動で緩めない。
6. 次の発言とアプリ再起動後の会話再開に、同じネイティブ会話を使う。会話の複製には別のネイティブ会話を割り当てる。

## 実行と保存

完成済みエージェントをLLMアダプタに偽装せず、Agentのターン実行を担当する独立エンジンとして接続する。既存のAgentライフサイクル・inbox・セッション記録・応答ストリームを共有する。外部ツールの実行済みイベントをHarnessのツールへ再実行させない。現行APIモデル経路は残す。

新規ルートは `codex-subscription` と `claude-subscription`。`default` は各ネイティブ実行エンジンの既定モデルを指し、実在未確認のモデルIDは登録しない。利用不能や未ログインを成功扱いせず、理由を表示する。利用上限到達・認証期限切れで停止し、API課金へ切り替えない。

既存ログ形式のイベント追加でエンジンとネイティブ会話の対応・実行状況を記録する。認証トークン・パスワードはセッションやブラウザへ渡さない。入力画像など対応できないコンテンツは送信前に明示的に拒否する。

## Host API

`session.subscriptionConnections()` は安全な接続情報のみ返す。

```json
[{"engine":"codex","name":"Codex","status":"connected"},{"engine":"claude","name":"Claude","status":"signed-out"}]
```

`session.connectSubscription({"engine":"codex"})` は公式のログインURLまたは手順を返す。APIキーやOAuthトークンは返さない。

```json
{"url":"https://auth.openai.com/...","message":"Complete sign in in your browser."}
```

## セキュリティ

各公式CLIのサブスク認証状態を実行前に照合する。APIキーの環境変数を継承せず、ユーザー設定のAPIプロバイダや代替ゲートウェイへ無断で接続しない。Host認証・Electronサンドボックス・コンテキスト分離は維持する。プロセスは既存subprocessサービスで所有し、停止・破棄時に終了させる。

## 検証範囲

利用者の指示により、自動テスト・lint・型検査は実行しない。起動に必要なemitとbundleだけ実行する。認証・有料枠消費を伴う推論を勝手に実行せず、実利用の未確認箇所を完了報告に明記する。
