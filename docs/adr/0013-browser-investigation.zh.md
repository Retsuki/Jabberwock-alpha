# ADR 0013：Worker 浏览器传输

[English](0013-browser-investigation.md) | 中文

状态：已接受。所有者于 2026-10-20 批准 ARTEX 式 Worker 浏览器操作和登录。

## Summary

拟议工具检查渲染页面，不新增范围或请求预算所有者。[规格](../specs/security-execution/browser-investigation-spec.zh.md) 定义首阶段能力及必须完成的隔离验证。方案 B 已批准。

## Alternatives

| 方案 | 实现 | 成本及影响 |
|---|---|---|
| A | 包装既有上游浏览器 MCP 提供者 | 初始变更小，但没有逐请求范围、固定 DNS 或共享预算的拦截入口，须跨额外进程添加策略 |
| B | 新增使用既有受检 HTTP 执行器的私有 Worker 浏览器适配器 | 独立浏览器生命周期；HTTP 策略及证据各只有一个所有者；明确验证通道隔离 |
| C | 将全部 Worker 工具传输替换为统一浏览器及网络网关 | 可统一后续工具，但需替换本能力以外的既有执行、授权及证据路径 |

推荐 B。C 还需迁移现有非浏览器 Worker 传输和执行，影响实现超过三倍。A 在上游工具入口仍缺少当前保证。

## Reconsideration

若请求可通过无所有者通道发出，或取消无法等待浏览器结束，则不启用 B。若多个适配器需要分别复制网络策略，重新评估 C；当前范围仅为一个浏览器适配器及一个共享 HTTP 执行器。
