# ADR 0007：独立安全服务

[English](0007-security-execution.md) | 中文

## 状态与决定

用户已批准。方案 B 提供独立安全服务，由任务界面与后续主聊天工具共用。首个里程碑是任务级主 Agent 会话与持久历史；随后再实现 Planner、Worker 协作及获批目标执行。参见[规格](../specs/security-execution/security-execution-spec.zh.md)。

## 替代方案

A 将现有原生聊天直接连接到诊断目标。其原生工具未建立任务范围强制，因此仅凭提示词无法形成边界。B 复用 Host 存储、Remote 身份与公网固定 DNS 传输，并独立拥有诊断计划及运行。C 重新设计整个代理/运行时基础设施；它重复已有服务并超出初始单请求里程碑。

规划里程碑通过主 Agent 接受明确请求，依据已保存任务配置及会话生成不可变计划。Host 要求五项设置检查全部通过、自动保存完成且任务版本未变；完整轮次身份防止重复交接。Planner 显示已记录尝试历史及待执行项目，不展示私有推理或虚构 Worker 指令。独立规划服务拥有持久队列，并运行禁用工具的 Planner Session。方案 A 将生成并入聊天服务，使独立生命周期耦合；B 以独立服务对象管理规划，并复用现有存储和 Agent 接口；C 在规划前重写全部运行时，重复已验证机制。继续采用已批准的 B。本阶段不增加原生工具桥接或诊断执行。

## 引导设置决定

方案 A 在每次自然语言回复后增加第二次模型调用以提取变更。它保留聊天显示，但推理次数加倍，回复成功与配置成功彼此分离。方案 B 为任务设置提供独立所有者和窄范围结构化会话引擎，复用现有禁用工具的 Claude 适配器及 Session 投影；验证后的回复保持可读，提案使用任务存储版本检查。方案 C 将主 Agent 替换为带任务更新工具的执行运行时；原生订阅循环需要新的工具桥接与权限设计，超出引导设置范围。用户已批准本阶段采用 B。若适配器要求通用循环中的特殊分支、无法记录安全结构化输出，或会话与设置出现冲突任务存储，则重新评估 B。

用户随后要求自动保存明确的设置回答。完整且验证通过的提案复用同一带版本检查的应用日志，不再逐项接受。保存失败及冲突会停止推进，不覆盖直接编辑。这只更改任务配置，不构成诊断执行批准。

## 主 Agent 模型选择

用户批准方案 B：保留任务会话所有权，增加经过验证且持久保存的引擎/模型选择。A 只添加 Claude 选择器，路由仍固定；C 替换订阅适配器，重复认证和 Session 所有权。B 将模型选择与执行权限分开，并保留任务会话。模型列表来自原生适配器，不在产品中硬编码。只有能够强制限制为纯会话的引擎才可选择；不支持的引擎明确显示不可用。如果切换必须削弱限制或将任务状态移入原生线程，则重新评估此设计。

## 影响

首个会话通道使用 Claude 并禁用原生工具，不改变普通聊天权限或引入 API 密钥。在能执行同等限制之前，此通道不提供 Codex。复用现有 Session 存储和原生订阅适配器；安全业务逻辑由独立所有者负责。

初始执行器允许一次有界公网匿名 GET，不跟随重定向，不允许任意 shell 或攻击操作。拒绝规则优先；未编译约束与未证实的原生规划路径会阻止执行。已停止运行不得因迟到响应变为成功，未结束运行在重启时变为中断。原生 Codex/Claude 规划接入前须独立证明禁用工具或仅经 Host broker 执行。

## 重新评估条件

如果安全逻辑开始进入通用 Session 或 API 控制器、界面与聊天出现两套状态或命令实现，或原生工具无法执行任务级权限，应重新评估职责划分。无法执行限制的通道保持断开，直到约束可用。

## 单个 Worker 与角色模型

已批准的 B 架构由独立服务持有 Worker 运行记录，与不可变 Planner 方案及可编辑任务分离。首个 Worker 仅接受明确选择的计划项、已登记资产和匿名 GET 的完整 URL。A 直接暴露原生 Shell，无法强制任务范围；C 重写现有传输及 Agent 生命周期，却没有新的约束收益。B 复用公共地址解析与固定地址连接，拒绝代理路由，先保存证据，再交由无工具模型整理。无法编译的自然语言限制阻止执行。后续攻击工具和并发 Worker 必须定义各自可强制执行的操作。

任务概览在任务记录中分别保存主 Agent、Planner 和 Worker 的模型选择，主 Agent 标题栏修改同一设置。任务无覆盖时仍读取旧主 Agent 映射，Planner 和 Worker 遵循下方自动/固定策略。新 Planner 或 Worker 捕获所选路由；设置变化不修改已运行调用。无法强制禁用工具的提供方仍不可选。

## 自动角色模型选择

所有者批准通过现有角色服务自动选择 Planner 和 Worker，不替换执行基架。主 Agent 选择 Planner，Planner 从实际安全目录为每个调查项选择 Worker，记录简短操作理由而非私有推理。所有者的固定偏好优先，仅影响新调用。这使模型委派与执行策略分开：模型选择不能扩大允许目标或工具。旧明确模型保持固定；未设置或默认选择变为自动。缺少模型决策的旧计划在自动执行 Worker 前须重新规划。

## Planner 反馈协调

已选择的 B 方案在现有 Planner 和 Worker 服务之外增加任务级执行协调器。界面直接编排（A）会在导航时失去执行归属与停止能力；重写现有执行服务（C）会丢弃经过测试的范围和持久化行为，不能增加所需能力。协调器保留明确授权目标、有限上限和子执行标识，并复用执行器。若并发 Worker 或新工具无法在不复制策略的情况下独立准入和停止，应重新评估此边界。

## 按资产范围调查

所有者授权在已保存任务资产和范围规则内调查，无需提供单个 URL。协调器为新运行捕获此范围；Planner 选择路径及登记根域下允许的子域，Worker 策略校验每个操作及解析地址。这复用现有准入、固定传输及生命周期归属，不授予原生工具。旧精确目标运行保持原限制，重启绝不恢复网络请求。

## DeepSeek 会话适配器

已批准的 B 方案通过仅供查找、无工具的引擎复用配置中的 DeepSeek 账户/API 目录，供各角色共享。在各角色中增加提供方分支（A）会重复路由及校验；替换现有引擎与执行服务（C）会丢弃已验证的所有权，却不增加能力。任务级可选共享许可保留旧记录，并将历史讨论共享限定为一个 Session 与目标。若新提供方需要文本会话以外的能力，或无法保留取消与提供方模型目录，应重新评估适配器。

## Worker 会话归属

所有者批准 B：扩展现有 Worker 服务，提供持久化、归属于运行的会话，复用模型与执行边界。仅显示历史的 A 无法在持久生命周期内接收所有者追加消息。C 重写执行会替换经过测试的范围和取消行为，却不能增加所需会话能力。ARTEX 风格视图记录公开指令、执行结果及回复，不展示私有推理。

追加消息只分析捕获的证据，不增加网络访问，使会话与 Planner 授权的操作分离。如果持续 Worker 工具使用或并行轮次需要独立的操作准入和取消，应重新评估此边界；输入框本身不授予这些能力。

## 活动投影决策

用户批准先将时间线连接到现有持久记录，再连接探索。B 共享确定性客户端投影与现有所有者作用域读取 API。A 在两个视图独立归并，容易产生不一致链接。C 增加第二个事件存储或替换协调器，重复现有历史。当原子跨服务快照或历史分页需要专用读取服务时重新评估 B。图中的边使用显式保存引用，不推断因果关系。

## 发现与针对性复测

所有者批准 B：由独立持久化服务管理发现、处置及复测历史，并与 Worker 共享现有有界 HTTP 传输及任务策略。A 将处置加入 Worker 历史会混合可变的用户决策与执行证据。C 重建执行运行时会引入无关生命周期风险。发现保留原始来源与证据；复测分别捕获输入、模型、会话及新观测。仅有证据支持的 fixed 结论且正常完成时，才自动转为已修复。失败及证据不足不能关闭发现。增加认证或非 GET 验证前应重新审视共享操作接口，不能隐式扩大现有传输能力。

## 响应存储与报告

所有者批准将捕获的 HTTP 字节与模型输入分离，并从保存记录生成报告。A 仅提高模型提示上限，仍耦合存储与推理。B 保留有界任务级响应文件、有界模型摘录与明确的捕获/分析缺口，并复用现有执行所有权。C 替换协调器及存储运行时，会引入无关的生命周期变更。B 区分部分捕获与执行失败，防止模型完成声明隐藏检查缺口。报告从保存记录生成，不再请求推理；零发现不表示整个资产安全。

## 标题栏令牌显示

所有者批准 B：复用现有会话用量投影，并为 Planner 与 Worker 共用标题栏显示。A 在各标题栏重复读取与计数。C 新增独立计量器及持久化总量，可能偏离会话历史。B 保持提供方测量为权威来源，无须变更执行或持久化。若可见活动会话无法在不启动推理轮次的前提下发布当前用量，则重新评估读取路径；令牌显示绝不能启动调查。

## 资产覆盖投影

用户要求与 ARTEX 等效的资产覆盖。继续采用已批准的只读投影方案 B：从已保存记录推导资产关系和观测数量，复用现有读取服务。A 为示例图增加独立计数会重复数据责任；C 新建覆盖存储和执行运行时会重复已有证据。B 不增加持久化或执行权限。登记范围决定分母，真实 HTTP 证据决定触达情况，未知范围不能表示完整覆盖。稳定 SVG 关系图提供拖动、平移、缩放及折叠，无需新增图形依赖。资产发现或记录规模需要权威分页时再评估服务端投影。

## 调查恢复

调查稳定化保留现有 Planner、Worker 和协调器的职责。模型边界的严格校验仍为依据；同一 Session 内有限次数的格式纠正处理可恢复响应错误，不在本地修补无效 JSON，也不重试已被策略拒绝的操作。显式继续建立关联的新执行，不修改原历史，也不在启动时自动恢复。已保存的终态观测和已消耗的请求／轮次预算继续归该执行链所有。任务修订变化时需要新调查。这项定向修正不增加运行时或存储。若持久化子任务记录无法在不猜测结果的情况下恢复待执行工作，再评估协调结构。

## 本地验证来源

所有者要求使用真实本地漏洞应用进行测试。现有共享请求策略允许显式配置精确 IPv4 环回 HTTP 来源，默认为空。这保留单一任务／资产／范围校验路径，并使用相同采集证据进行模型驱动发现导入。仅测试绕过不能验证真实准入；新网络运行时会重复地址固定和采集职责。精确配置来源在不改变公网解析、不开放局域网发现的前提下限定本地验证。支持一般私网、基于主机名的本地目标或认证请求前应重新评估策略表示。


## 管理层报告呈现的归属

获批 B 设计将纯管理层投影及主题章节渲染与现有规范报告和导出分离。仅装饰 Markdown DOM（A）难以一致表达数量／状态差异与紧凑摘要；重建报告生成／存储（C）会为展示需求重复证据及执行归属。投影不请求模型或修改持久化记录。仅当独立撰写、可审阅的业务评估需要自己的持久化生命周期时重新考虑生成归属。

## 原生结构化设置输出

针对反复出现的设置响应格式错误，用户批准 B：通过执行请求和 Claude SDK 原生输出格式选项传递现有已记录的 JSON Schema，并保留原有严格提案解析器。A 继续仅依赖提示纠正，无法强制原生结果格式；C 替换已有会话运行时及其所有权与持久化。B 不增加目标访问或通用工具能力。

SDK 成功不保证结构化输出存在；缺失或无效输出均失败。仅在明确请求 schema 时接受精确内部名称 `StructuredOutput`，两条权限路径均验证输入；实际工具仍拒绝。原生主聊天或 host-tools 路由指定 schema 会明确失败，其他引擎保留当前文本验证行为。如果 SDK 无法在不暴露外部能力的情况下强制隔离内部载体，则重新评估此选择。不改变 Session schema 或持久化格式。
