# ADR 0014：主聊天安全操作

[English](0014-main-chat-security-control.md) | 中文

## 摘要

所有者已批准 B 方案：一个绑定工作区的公共操作服务，将普通主聊天工具连接至现有安全服务负责人。浏览器调查不在范围内。[功能规格](../specs/security-execution/main-chat-control-spec.zh.md)定义所需行为。

## 备选方案

| 方案 | 结构 | 取舍 |
| --- | --- | --- |
| A | 为每种操作添加独立聊天分支 | 初期改动小，但不同入口的工作区和更新规则会分歧。 |
| B，已批准 | 通过公共操作负责人验证并委托 | 保留现有存储和执行行为，同时分离聊天展示。 |
| C | 围绕新控制器重建聊天、任务界面和执行 | 替换既有的执行、取消和证据责任，范围显著更大。 |

## 决定

普通聊天是另一个面向所有者的控制入口，不是另一个安全代理运行时。操作负责人从调用 Session 解析工作区，并委托现有服务。任务界面和主聊天共享保存状态、执行准入和 Worker 指示。依赖不可用或请求被拒绝时，必须明确失败。

预计不增加持久化模式或环境变量。模型不能通过该适配器覆盖工作区身份、绕过缺失的设置检查项、扩大目标授权，或在重启时重放网络工作。

## 重新评估条件

如果界面和聊天必须维护独立的修改逻辑、无法从可信 Session 元数据推导工作区访问，或新流程无法通过现有执行责任表达，则重新评估公共负责人。不得通过向模型暴露原始记录写入或通用进程执行来解决这些问题。
