# ADR 0005：使用原生客户端组件整合安全工作区

[English](0005-security-ui-migration.md) | 中文

## 决定

用户于 2026-10-17 批准方案 B：将 Next.js 原型中可复用的 React 视图结构和领域数据提取为 Jabberwock 客户端插件。现有各工作区负责自身安全视图和隔离的本地草稿。`ui-workspace` 在项目行下提供通用子插槽；`ui-security` 提供折叠菜单并按工作区 ID 与视图导航。独立的全局 Security 入口和项目选择器不再作为用户入口；现有聊天负责会话和引擎权限。现有控件和主题标记使两个区域具有一致的交互语言。

## 备选方案

A 嵌入单独运行的 Next.js 应用。它保留原型代码，但增加第二套运行时、路由系统和部署要求。B 通过现有主面板与侧栏注册 API 复用领域类型和页面结构；替换界面包装而不导入 shadcn。C 重建整个安全界面和数据模型。C 提供全新起点，但丢弃有用的原型行为，同时仍需未来的实际诊断服务。B 以最小依赖增量实现迁移目标。

## 影响与重新评估条件

新工作区的安全视图从空状态开始，并明确提示执行尚未连接。旧演示记录独立保留，不执行网络扫描或模型调用。其本地状态独立于 Host 凭据和 Session 持久化。范围和保全条件见[规格](../specs/security-ui-migration/security-ui-migration-spec.zh.md)。

连接实际诊断执行或跨窗口与用户共享安全状态之前，应重新评估设计。客户端 localStorage 不能成为执行审批、审计记录或企业发现的权威。如果现有控件无法表达必要页面，应暂缓该页面并向用户提出具体依赖方案，不得静默引入 shadcn。满足迁移和保全条件之前保留原型。
