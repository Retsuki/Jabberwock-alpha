# ADR 0006：Host 拥有的安全持久化

[English](0006-security-persistence.md) | 中文

## 决策

用户于 2026-10-17 批准 B 方案：复用现有 Host 存储与已认证 Remote 基础设施，由安全管理拥有独立持久记录。工作区身份隔离企业范围、分类资产及未执行的任务草稿。桌面存储域提供者拥有 SQLite；已保存的业务记录不由浏览器组件生命周期管理。参见[规范](../specs/security-persistence/security-persistence-spec.zh.md)。

## 替代方案

A 在现有浏览器预览存储中添加持久化。它减少 Host 工作，但将记录绑定到来源，并使已保存任务与未来执行所有权分离。B 在现有 Host 服务旁增加安全管理所有者，同时保留现有 UI。C 全面替换安全应用及执行基础设施。C 重复现有认证、工作区和存储机制，对首个重启后保存流程没有帮助。

## 影响

保存成功须获得 Host 存储确认。空工作区不接收演示种子，旧浏览器值保持不变。已保存任务保持草稿：持久化既不授予目标访问权，也不启动诊断。现有执行权限和 Session 格式不变。任务详情预览不得将示例证据呈现为已保存任务的结果。

连接运行时操作前，须分别设计执行、目标约束、Planner/Worker 协调与证据存储。已批准的首个阶段仅包括资产与任务持久化；本决策不表示运行时验收已经通过。

已批准的概览编辑延续采用 B：可选类型化任务策略数组复用聚合与 CAS 保存队列。A 将行保留在本地组件状态，无法跨重启保留；C 重新设计任务存储与 API，在本阶段没有必要且重复现有版本控制。已保存的允许/禁止草稿并非已执行的运行时策略。
