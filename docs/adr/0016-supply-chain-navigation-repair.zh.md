# ADR 0016：供应链导航与修复职责

[English](0016-supply-chain-navigation-repair.md) | 中文

## 摘要

所有者批准 B：复用固定扫描器与已保存 Session 历史，通过单个 Security 目的地提供标签式检查导航，并将依赖修复置于独立操作负责方。[规格](../specs/supply-chain-check/supply-chain-check-spec.zh.md)定义行为；实现已完成，功能验证文档记录已执行检查与剩余限制。

## 备选方案

| 选项 | 结构 | 权衡 |
| --- | --- | --- |
| A | 在聊天中增加列表和修复分支 | 将修改策略与对话展示耦合。 |
| B，已批准 | 复用扫描器／历史并独立修复职责 | 保持只读检查与明确项目文件更新互相独立。 |
| C | 重建扫描器、历史和导航 | 以更大变更替换现有持久化与取消机制。 |

## 决定

Security 页面负责 Assets、Tasks 和 Supply-chain 导航。检查详情嵌入现有 Session 对话与事实报告，不重复历史。扫描服务负责公告事实、列表／读取和已保存结果。独立修复负责方验证明确的单项／批量操作，在禁用脚本／钩子及隔离环境／配置下暂存固定 npm／pnpm 仅锁文件更新，刷新全部公告并检查原文件哈希，再备份应用 manifest／锁文件变更并复扫。

初始修复仅覆盖独立项目的公开直接依赖。扫描不代表允许修复。修复不更新 node_modules，也不证明应用健康。缺少验证保持未验证；公告数量降低不能使其成为成功。报告完成之前，Host 约定及任何持久化类型变更必须通过现有机制验证。

## 重新考虑条件

若支持修复需要工作区范围或私有依赖解析、任意项目生命周期脚本、冲突的修改负责方，或无法保留原文件的回滚，应重新评估 B。不得静默扩大固定操作，也不得将无限制 shell 执行交给聊天。
