# ADR 0012：共享探索的所有权

[English](0012-shared-exploration.md) | 中文

## Summary

方案 B 新增一个共享探索服务，同时保留任务、执行、证据及发现的既有所有者。参考 ARTEX 的类型化探索节点、关系及按角色区分的读写。所有者已批准 B。

## Alternatives

| 方案 | 结构 | 影响 |
|---|---|---|
| A | 在每个计划和 Worker 记录附加共享摘要 | 初始成本最低，但并发更新、重复副本和关系查询仍分散 |
| B | 共享注释和关系由专用服务管理，原始记录保留所有者 | 新增服务和限定 Agent 访问，连接现有执行与 UI，不迁移全部记录 |
| C | 用单一探索存储替换任务、计划、Worker 和发现持久化 | 持久化统一，但必须修改执行、再测试、报告、兼容处理及所有读取者 |

推荐 B。C 还需迁移既有生命周期和证据存储，工作量明显超过 B 的三倍；A 让多个写入者缺少共同提交所有者。

## Scope

[规格](../specs/security-execution/shared-exploration-spec.zh.md) 定义记录、角色权限、幂等、模型日志及验收。首阶段将现有调查接入共享信息，不增加网络工具或扩大目标权限。

## Reconsideration

若普通图读取依赖各来源所有者同步互相更新，或部分应用失败无法在派发前确定性修复，应重新评估存储划分。替换时保持来源引用和重试标识稳定。
