# ADR 0002: サブスク実行を独立エンジンとして扱う

## 背景

Jabberwockの主チャットから、APIキーを使わず契約中のCodexとClaudeを利用する。既存外部プロバイダは単発のサブエージェントで、会話継続と人間の承認を提供しない。

## 選択肢と決定

Aは既存サブエージェントの有効化、Bは単発プロバイダの拡張、Cはターン実行部分を独立した切替式エンジンとして再設計する。2026-10-17に利用者がCを承認した。画面と会話のライフサイクルを保持し、推論とネイティブツール実行は各公式エンジンへ委譲する。外部エージェントをLLMに見せかけず、既存APIモデル経路とも分離する。

## 撤退ライン

公式の認証条件が変わりサブスク利用ができなくなった場合は当該エンジンを利用不可として案内し、APIキーへ自動転換しない。既存セッションの互換性や承認の安全性を維持できない場合は組み込みを止めて設計を見直す。
