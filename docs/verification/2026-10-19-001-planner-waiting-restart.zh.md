# Planner 等待记录的重启验证

[English](2026-10-19-001-planner-waiting-restart.md) | 中文

## Observation

重启后原生任务显示执行读取失败并禁用调查启动。桌面数据目录和任务资产配置未变。保存的计划共 32 条，其中一条就绪 continue 决策没有新项目，捕获两个运行中 Worker，且没有停止标识。

## Hypotheses and evidence

若存储或配置目录不一致，应缺少任务记录；实际存在预期任务、资产及 32 条计划。若读取器拒绝有效等待输出，应在初始化发生；读取器拒绝所有无项目的非终态就绪计划，恰好匹配该等待决策。现有 UI 未暴露此启动校验细节，因此直接只读检查持久化结构及初始化条件，没有修改数据。

## Resolution

启动读取器与响应准入使用相同验证，只在捕获的 Worker 中存在未停止项时接收仅等待的审查计划。空初始提案和无效停止标识仍被拒绝。相关重启回归测试通过。原生恢复已通过，使用的记录未修改。本地 Claude 验证执行六个 Worker，保留七条发布事实并应用三轮 Planner 审查；后续 Planner 快照包含四条及七条共享事实，并明确引用这些事实。执行在配置的请求预算处停止，剩余工作保持未验证。原生探索界面显示已提交事实及支持关系。最终 UI 还按记录的发布时间把新事实放入时间线；旧事实没有时间戳时不伪造事件。
