## 范围

原生桌面应用使用 Claude Sonnet 5.5 的新普通主聊天。Session `session-0a7b5b36-7b77-4de6-95e6-c356fb403861` 操作虚构任务 `0bd34466-6c4d-4c63-a7c4-340bbea86cd6`，目标是已登记的本地夹具 `http://127.0.0.1:43188`。本次测试不包括外部目标调查。

## 观察到的控制

记录的原生主机工具调用成功列出任务、创建虚构任务、更新任务、读取状态、返回显式任务导航并停止空闲任务。任务按钮打开实际概览和任务 Sessions；概览显示已保存的目标和说明。Planner 和 Worker 模型选项保存为固定 Claude `sonnet`。

初次设置确认因模型序列化的指纹与 Host 表示不同而失败。公共 `normalizeSecuritySetup` 现由 Host 推导这些指纹。重复更新在修订 31 成功，原生检查清单显示全部五项已确认。该结果不代表目标调查已经启动。

## 调查边界

明确的调查启动消息到达 Claude，但 Claude 拒绝，且没有记录 `start` 主机工具调用。保存的执行、计划和 Worker 数量仍为零。未尝试绕过防护。因此，本次测试验证会话读取、草稿修改、导航和空闲取消，但未验证主聊天驱动的实际调查、运行中取消、恢复或实时 Worker 补充指示。操作委托路径有定向测试；它们不能替代缺失的真实模型端到端结果。

Codex 原生控制没有兼容的主机工具桥接。没有测试真实 DeepSeek 主聊天模型执行；其 Harness 适配器有定向测试覆盖。
