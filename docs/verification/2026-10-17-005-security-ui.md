# セキュリティ画面移植の確認記録

English | [中文](2026-10-17-005-security-ui.zh.md)

## 実装範囲

`packages/client/ui-security` をサイドバーとメイン画面に登録した。プロジェクト・資産・診断タスクと10種の詳細タブ・発見事項詳細・エージェント一覧を既存UI部品で表示する。診断とAI実行は未接続で、デモ表示を常設する。独立した版付き保存キーでプロジェクト、登録資産、準備診断を保存する。旧プロトタイプの保存領域と既存チャットは変更しない。

## 実行した確認

統合担当が対象TypeScript検査・lint・バンドルの終了コード0と `verify-client-packages` の成功を確認した。`build:check` はHost・Client aggregateの2検査を通過した。これは最後のCSS見直し前の実行であり、その後は対象TypeScript検査・lint・バンドルを再実行して通過した。全体のJSDoc・UI i18n検査には既存所見が残るが、新規ui-securityの所見は0件だった。テストスイートは実行していない。

統合担当が実デスクトップでProjects・Assets・診断詳細10タブ・発見事項詳細・Agentsの表示を確認した。プロジェクト作成、空状態、有効・重複・不正入力を含む資産登録、準備診断作成、再読み込み後の復元、1280幅の表示、既存チャットのcontenteditable入力欄の表示を操作確認した。確認用データは削除した。`verify.py ui` に画面 `Security:空のプロジェクト` と端境条件 `資産0件` を登録した。

証跡画像は `.local-runtime/verification/2026-10-17-security-ui/` に保存した。ファイル名は `jabberwock-security-projects-final.png`、`jabberwock-security-overview-final.png`、`jabberwock-security-finding.png`、`jabberwock-security-agents.png`、`jabberwock-security-empty.png`、`jabberwock-security-narrow.png`。これらはローカル実行資料で、公開用成果物ではない。

## 静的レビューと未確認

別担当が主要5ファイルを読み、実診断APIがないこと、旧プロトタイプへの依存がないこと、不正な保存値を上書きせず変更操作を止めること、書込失敗の通知、既存チャットとの分離を確認した。不正保存の実アプリ注入や書込失敗の再現は行っていない。複数ウィンドウの同時編集には競合対策がなく、後の書込が優先される。

G6カバレッジ図、実診断、実AI、Next.js専用チャット、旧ブラウザ保存データの自動移行は保留している。必要資料と旧データの保全を確認するまで `jabberwock2/` を維持する。コミット・pushはしていない。

## 起動に関する留意点

UI更新中にwatcherと手動バンドルを同時実行した際、import失敗から起動待ちになる事象が1回発生した。コードは変更せず、処理安定後に `start:desktop` で再起動して復帰した。記録時点ではその方法で実アプリが起動している。開発モードの再読み込み安定性は今回の確認では保証しない。
