# security-report

## 手順

1. `read` の `executions`、`findings`、`retests` を読み、実行中・完了・失敗・未実行を区別する。取得した結果の深刻度、状態、概要、対処案、再検証結果を要約する。
2. `read` は要約であり証拠本文や網羅性を含むとは限らない。証拠や検査済み範囲を推測しない。未解決・未検証・結果無し・切り詰めを区別し、発見0件を安全と言い換えない。
3. `open` に `taskId` と `view:"report"` を渡す。ツール結果のナビゲーションを使い架空URLを作らない。空でも導線を返し、未完了なら途中経過と伝える。
4. 導線を返したことを報告する。ユーザーが画面を開いた、ファイルを書き出した、外部送信したと言わない。

表示依頼に `start`、`resume`、`message` を使わない。読込・表示失敗は説明し、診断のやり直しで埋めない。
