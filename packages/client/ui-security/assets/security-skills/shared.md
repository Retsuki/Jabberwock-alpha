## 利用条件

現在の Workspace のオーナーメインチャットで `security_control` を使う。引数は `{"command":{...}}`。Workspace は Host が決めるため `workspaceId` は渡さない。ツールが無ければ操作できないと伝え、Workspace の「セキュリティ」画面を案内する。保存ファイルの直接編集、シェル、外部への直接リクエスト、UI 自動操作で代替しない。

対象が不明なら `list` で登録資産とタスクを読む。複数候補なら確認し ID を推測しない。対象を決めたら `read` に `taskId` を渡す。返却の `data` は JSON 文字列。`truncated:true` なら内容を補完せず、一覧は `offset` / `limit`（1〜100）でページ送りし、詳細は `open` で案内する。

`/security-task` などはHarnessがスキル本文を読み込むジェスチャーであり、プロバイダー固有のコマンドではない。本文が読み込まれている場合、ネイティブコマンドが無いことを理由にスキル自体が存在しないと案内しない。
