## 概述

<a id="browser-state"></a>
## 浏览器状态

旧 `jabberwock.security.v1` localStorage 记录包含带版本号的项目、已注册目标和诊断草稿。旧项目及草稿继续保留，不会自动分配或复制到现有 Workspace。项目资产界面不会读取或写入这些记录；也不会读取、修改或删除原型的 `artex-state-v1` 记录。

[安全子系统参考](../../../docs/subsystems/security.zh.md)负责生成的 Host API 列表。`SecurityRecords` 是 Workspace 的原子聚合，包含其带品牌类型的 Workspace 标识、修订号、企业、资产和任务草稿。`security-records/changed` 事件仅在存储写入成功后携带已提交的聚合。Host 通过 `securityRecords.read/save` 和 `jabberwock_security` 存储域拥有企业范围、分类资产与任务草稿。桌面存储使用配置的现有提供者。保存成功须等待持久确认；过期版本需重新加载，写入失败保留最近确认的快照。空工作区不接收示例种子。资产范围修改不会自动发现资产，也不影响实际访问控制。

任务概览编辑将可选目标、操作约束和范围规则行保存到任务草稿。各行支持原位编辑、空草稿和删除，复用现有 500 ms 自动保存队列，并在失焦/导航时提交待保存内容。旧记录缺失数组时显示为空，存储域保持版本 1。这些已保存意图不执行运行时权限控制。可选字段没有模式默认值：虚拟初始行在编辑前不写入数据。

安全任务会话、Planner 规划、Worker 调查与追加讨论保留在任务 Sessions 视图。安全插件为保留的生成 Session 标识注册可撤销的侧栏可见性规则，覆盖旧历史。普通未命名聊天仍可见；该规则不会删除或归档任何 Session。

<a id="screens"></a>
## 界面

分组侧栏中每个实际 Workspace 提供单个安全入口，页面提供资产、任务与供应链标签。 选择菜单后打开对应 Workspace 的安全主面板；重命名 Workspace 后标题同步更新。虚拟文件夹、 未分组 Session、扁平列表和搜索结果不会创建虚构的 Workspace 菜单。旧独立项目选择器不再出现在此路径。 项目资产提供企业、根域名、IP、子域名、应用、服务和端点七种分类视图。企业范围对话框支持替换或追加域名、IP 和 CIDR 目标。企业和资产变更按工作区保存；删除资产会移除任务引用。新建任务需要名称和至少一项已注册资产，保存描述/目标为空的未执行草稿，并在 Sessions 打开主 Agent。创建按钮说明会将所选任务上下文发送给 Claude，开始引导设置；打开旧任务不会启动推理。草稿保存名称、描述、目标及选定资产 ID；置顶、归档和删除均为持久变更。分类、并发和执行控件不可用。 任务详情提供会话、概览、探索、时间线、发现、复测、资产、覆盖范围、审批和报告选项卡。已保存任务的时间线和探索显示持久活动；预览任务和资产覆盖图保留独立示例数据。预览审批和复测操作不会执行请求；保存任务的复测使用独立发现服务。报告复制会将显示的示例以 Markdown 格式写入剪贴板。

插件将日语注册为可选语言，并以英语回退，不改变现有语言选择。界面文本由英、中、日词典管理； 迁移的示例内容保留原始语言。在 Settings → General → Language 中选择「日本語」，可使用日语资产、任务、会话和调查计划控件。

任务 ID 和详情按钮打开独立详情视图，标题与选项卡栏固定显示。概览包含目标、操作约束、资产规则、覆盖度、Token 用量和任务状态卡片。已保存任务元数据与演示面板分开；这些面板不提供执行结果或持久详情编辑。旧浏览器记录与 Host 存储独立保留。

已保存任务的 Sessions 呈现持久主 Agent 会话和可独立选择的 Planner 方案。主 Agent 标题栏通过 `securityConversations.catalog` 读取可用订阅引擎和模型，通过 `securityConversations.select` 保存任务专属选择。选择从下一条消息开始应用，不替换 Session 或输入草稿；运行中的轮次和待确认变更期间禁用控件。请求失败时保留原显示并提供重新加载。Codex 原生协议无法强制纯会话权限，因此保持禁用。会话项在角色标题下缩进，角色分组之间保留间距，并用现有线框图标标识角色。Planner 面板显示已记录尝试状态、时间戳、快照及待执行调查项，提供刷新与取消。不展示私有推理，不虚构 Worker 派发或结果。计划创建通过会话请求，不提供独立创建按钮。旧浏览器演示保留本地示例会话，不向 AI 发送消息。附件仍禁用。

主 Agent 标题栏可切换默认显示的只读设置清单，可从清单直接打开同一任务的概要。已保存任务事实决定目标/完成标准、范围、许可、操作限制和执行上限的状态。主 Agent 每次询问一项缺失信息；完整回复中的有效设置按版本检查自动保存，再询问下一项。普通会话不显示确认按钮。保存或后续提问失败时提供重试操作；直接编辑冲突时需在会话中重新讨论设置，不会覆盖。记录版本变化会刷新概览，同时保留未保存的手动编辑。重要范围编辑使范围和许可确认失效；目标编辑需要新的完成标准。概览持续显示已保存的完成标准和上限。通过会话交接 Planner 时，旧任务同样需要完成五项检查；设置完成只允许规划，不代表执行目标操作。

设置指示包含完整响应 schema 和每个范围规则字段。完整单一 JSON 代码围栏采用相同的严格字段校验；拒绝回复不隐含执行动作。完整响应的 JSON 或 schema 字段无效时，允许同一引擎/模型进行一次仅格式纠正；原始任务上下文和所有者动作仍为权威依据。Session 记录纠正输入及先前原始响应，两次尝试的用量均计入。提供方失败、非 stop 完成、取消、存储失败和解析后的任务/模型授权失败不重试。完整自由文本（包括拒绝说明）可能收到这次仅格式纠正；不推断拒绝语义，也不绕过限制。两次响应仍无效时不更改任务设置，并显示本地化的重发提示。

<a id="role-models-and-one-bounded-worker"></a>
## 角色模型与单个受限 Worker

概览将主 Agent 选择保存在 `task.agentModels`，通过 `task.agentModelModes` 为 Planner 和 Worker 提供自动或固定选择。自动模式下，主 Agent 请求规划时选择目录中的 Planner 模型并给出简短理由，Planner 为每个调查项选择目录中的 Worker 模型和理由。Host 验证实际目录 ID；`default` 不代表自动决策。所有者固定偏好优先。明确的会话偏好通过设置日志保存，不会为不支持的提供方编造配置。设置仅影响新调用，运行记录保留实际选择和理由。缺少模式时，旧明确模型按固定处理，未设置或默认模型按自动处理。旧计划仍可读取；自动 Worker 执行前必须重新生成缺少项目模型决策的计划。主 Agent 标题栏继续修改共享选择；无法强制禁用工具的提供方保持不可选。

新调查从任务已保存的登记资产与范围规则开始；执行表单与单个项目均不要求所有者输入 URL。Planner 分配调查，Worker 逐步选择经过检查的工具。`securityWorkers.start/read/cancel` 在 `jabberwock_security_workers` 中持有独立于任务和计划项的运行记录。工具包括 HTTP 请求、已保存证据的额外窗口以及私有临时文件。支持查询参数；非只读 HTTP 方法和携带凭据的请求需要明确保存的许可，并逐次获得所有者批准。重定向作为观测返回，不自动跟随；目标地址必须通过新的检查请求。代理、非公共地址、排除范围、不支持的自然语言限制和过期计划均拒绝执行。每次请求重新检查公共 DNS 并固定地址。下一模型步骤开始前保存观测及模型可见工具活动。发现引用其支持观测，失败保留已取得证据。历史单次 GET 运行保持可读。

配置项 `workerTimeoutMs`（15000）、`workerMaxResponseBytes`（4194304）、`workerModelResponseBytes`（65536）、`workerModelTimeoutMs`（180000）记录到每次新运行快照。响应捕获与每次模型文本预算相互独立；请求、工具调用和模型步骤也有有限预算。有限上限不代表可编译任意文字停止条件。Claude 订阅 Worker 只公开显式注册的进程内 MCP 工具，禁用原生工具、子代理、技能与插件。DeepSeek 账户/API 循环使用相同的显式能力，但真实模型验证尚未完成。尚不支持 Codex Worker。派发采用滚动池；Worker 清理完成后释放空位。

离线命令工具仅支持 macOS，并依赖托管子进程服务。默认拒绝的 Seatbelt 配置阻止网络、无关项目/主目录读取及进程派生。命令只能单进程运行：不支持管道、后台任务和需要子进程的脚本。其他主机拒绝执行，不回退到未隔离进程。HTTP 流量始终使用经过检查的 HTTP 工具。

<a id="planner-feedback-execution"></a>
## Planner 反馈执行

主 Agent 从已保存资产和范围规则启动所有者委托的调查，Planner 展示活动和停止控件。`securityExecution` 独立于可编辑任务记录，捕获 `targetMode: asset-scope`、任务及资产快照、轮次、子执行标识与决策。Planner 分配范围内的调查，接收已保存的 Worker 多步骤观察并决定继续、完成或需要输入。每个新操作按捕获的资产范围与拒绝优先规则校验，请求时还须检查公共地址。没有此模式的旧执行保持精确目标限制并可读取。停止等待所属子执行结束，操作设置变化停止派发，重启不恢复请求。面板显示进度和保留决策。此有限工具执行流程尚未达到完整 ARTEX 工具集的能力。保存报告描述实际观察和缺口。

自由文本 `task.setup.limits` 记录所有者要求的限制，不配置实际执行预算。`security_control.read.executionLimits` 提供新调查的 Host 实际限制。技能在开始前比较已保存要求和实际限制；不一致时需要澄清，不能假定文本会被强制执行。恢复运行保留其已保存执行快照中的限制，通过 `executions[row].limits` 返回；开始／恢复结果也包含各运行的快照限制。`executionLimits` 仅用于新调查，恢复时使用所选运行的限制。

`executionMaxConcurrentWorkers` 配置同时运行的 Worker 数，范围 1–10，默认 3。新执行保存此上限，旧快照缺失时保持串行。空位领取待办，无需等待整批完成。持久化派发预留划分共享 HTTP 额度，清理完成后归还未使用额度。手动启动不能绕过活动协调器。指令、审批及单独取消按 Worker 运行定位；任务取消阻止排队准入并等待所有子操作。一个 Worker 结束后即可触发一次 Planner 审查，其他 Worker 继续运行。审查期间暂停新派发，后来完成的结果留待下一轮。持久化审查标识区分本次结果和运行中进度，并记录决策是否应用。仅停止明确指定的运行中 Worker；替换待办队列不会取消它们。显式恢复只应用一次已保存的就绪决策，重启仍不自动执行。

<a id="shared-exploration"></a>
## 共享探索

Planner 与 Worker 通过 `securityExploration` 共享目标、调查、HTTP 观察、有证据关联的事实、发现及未验证提示。原始记录保留既有所有者，新的任务域仅保存注释和支持关系。Worker 使用 `read_exploration` 读取共享知识，使用 `publish_fact` 保存附有自身保留观察原文引用的主张。Planner 保存有日志记录的共享输入，并可返回调查关联、提示和有证据关联的目标评估。评估不改变任务完成状态或发现处理状态。就绪注释在派发前幂等应用；应用失败阻止依赖操作。任务级串行写入保留并发结果；设置过期使目标评估失效，但不删除证据。`explorationModelBytes` 限制完整模型读取的序列化容量，默认 65536，范围 1024–1048576；截断视图报告省略记录，Worker 可请求指定节点。所有者图读取保留完整投影。这些输入消耗模型 token 并使用既有工具调用上限，不增加目标权限。

<a id="main-chat-control"></a>
## 主聊天控制

恰好登记到一个 Workspace 的普通所有者聊天获得 `security_control`。原生 Claude 使用进程内主机工具桥接；普通 Harness 路由向 DeepSeek 提供同一命令。Codex 没有兼容的主机工具桥接，不能执行这些控制。专用安全 Session、受委托代理和非所有者调用者不会获得所有者控制权限。工作区身份来自实时调用 Session，不来自模型参数。

所有者可以要求“列出安全任务”“使用这个已登记资产创建任务”“修改这个任务的目标”“开始这个任务的调查”“停止这个任务”或“打开这个任务的发现事项”。工具列出资产和任务摘要，读取保存的配置与进度，创建或更新任务草稿，将开始／恢复／停止委托现有执行负责人，并向指定的现有 Worker 发送补充指示。它不会直接给 Planner 发消息。显式 `open` 结果提供任务界面按钮；点击后重新验证任务，并在导航前保存待处理编辑。导航失败保持可见。

修改使用当前保存的修订，并拒绝冲突编辑。创建使用限定于调用 Session 的稳定请求标识；重试保留该标识。设置确认要求精确引用当前所有者消息，不能猜测权限。开始和恢复要求当前所有者明确提出调查请求，并通过既有检查清单和执行检查。停止等待所属执行、规划和 Worker 取消完成。工作被接受不等于工作已完成。工具输入和结果保留在调用 Session 的常规历史中；现有提供商同意仍生效。

`plan` 操作携带当前修订和稳定重试标识，委托既有规划服务。它返回已保存的规划尝试，不派发 Worker，也不访问目标。规划保留设置检查清单、模型选择和活动会话准入检查。读取结果在同一输出限制内包含已保存的 Planner 和 Worker 失败原因。

`controlModelBytes` 限制完整序列化工具结果，包括导航坐标（默认 65536，范围 1024–1048576）。超限结果明确说明截断。列表分页和显式任务读取可缩小结果；不得推断省略内容。不引入新的持久化域或重启自动执行。[已批准设计](../../../docs/adr/0014-main-chat-security-control.zh.md)记录公共操作责任。

<a id="conversational-investigation-handoff"></a>
## 会话调查交接

主 Agent 区分仅规划请求和当前所有者明确委托调查的请求。完整的结构化调查动作先保存任务编辑，再校验准备状态与目录中的 Planner 模型，并通过稳定请求标识启动任务级协调器。协调器管理初始规划和后续 Worker 反馈，不会静默复用缺少自动模型决策的旧计划。读取任务或自动继续设置不会启动目标访问。

Sessions 显示主 Agent、Planner、系统审计和实际的独立 Worker 条目。新运行出现时保留 Worker 标识及状态，选择一个条目会打开归属于该运行的会话及可展开执行证据。Planner 显示紧凑且可展开的轮次活动及决策。主 Agent 的“开始调查”按钮发送与聊天相同的明确委托消息，保留尚未发送的草稿；Planner 保留进度和停止操作，不显示模型私有推理或虚构工具活动。

支持的操作描述在派发前与传输前根据每次请求的方法与凭据使用进行校验。明确的 HTTP 观察、横幅检查与服务/版本观察权限不会启用端口扫描或利用工具。只读规则拒绝写请求；认证和非只读操作还要求已保存的许可与所有者批准。这些许可不引入利用、暴力破解或压力测试能力。仅 HTTPS 与禁止 GET 会限制实际请求；未知或含糊的约束会停止执行，并标明未支持的文字。这些校验限制 Worker 请求，不保证远程服务器的行为。已确认的操作设置必须与保存的约束一致；缺少确认元数据的旧任务仍可读取。

现有提供方目录向三个角色提供 DeepSeek 账户及 API 模型。两条路由保留独立标识，不会互相回退或更换模型。主 Agent 会话保持无工具；专用 Worker 路由只公开该运行的能力。真实 DeepSeek 模型执行尚未验证。只有对该任务 Session 与 DeepSeek 目标授权后才共享历史讨论；始终允许的决定保存在该任务会话中。模型选择与自动决策复用 Claude 的保存控件。不可用的提供方或模型保持不可用，旧 Claude/Codex 记录保持原有含义。

<a id="worker-conversation"></a>
## Worker 会话

独立 Worker 打开归属于运行的会话，显示 Planner 指令、实际工具日志与 HTTP 证据、Worker 报告、关联的 Planner 复核及所有者追加消息。已就绪保存计划只为其引用的 Worker 运行提供实际复核摘要，条目标识稳定地由计划派生。请求/证据详情可在会话中展开，不展示私有推理。运行中与已完成视图在重启后保留已保存历史，标题/输入框固定，消息独立滚动。调查和追加回复期间，Worker 列表与会话显示加载动画；减少动态效果偏好会停用旋转。

所有者追加消息使用捕获的无工具模型讨论现有证据，不会请求另一个 URL、重启 HTTP 或启用 shell 执行。新调查操作仍由 Planner 负责。Host 检查任务/运行所有权并去重重试。初始运行时可排队一条指令，其分析等待该操作结束。活动或排队追加消息阻止再次提交。会话状态不替换原始执行状态；取消所选运行也会停止其活动或排队讨论。失败、取消及中断的回复始终区别于已完成报告。没有会话字段的旧运行仍可读取。

<a id="timeline-and-exploration"></a>
## 时间线与探索

已保存任务从现有计划、Worker 和执行记录读取活动，不触发推理或目标访问。时间线支持搜索、筛选、时间排序、真正的刷新暂停/恢复，以及可展开的元数据、关联记录和载荷。探索共享稳定标识和已记录关系；双指滚动平移、触控板捏合以指针为中心缩放，选择节点突出相关连线，可滚动详情面板默认折叠原始载荷。当前目标与资产上下文不表示历史创建或已达成；观察和模型报告不表示已确认漏洞。读取失败保留先前视图并显示错误。

<a id="findings-and-retests"></a>
## 发现与复测

关联重复发现时保留原始证据和 Worker 身份。自动关联要求匿名读取上下文、资产、方法、完整 URL、规范化标题、严重程度和证据原文完全一致；上下文未知或经过认证的记录保持独立。用户可关联或分离同一资产的报告，明确分离的决定持久保存。列表与报告展示代表发现及可展开的相关证据。再测试历史保留原始发现引用。

保存任务的发现仅导入已完成 Worker 的结构化报告，并引用保留的 HTTP 证据。用户分别管理处置状态，原始证据及来源标识持久保留。旧叙述摘要不会自动成为发现。 完整的开头 JSON 对象或代码块后可有解释性文字；只有对象提供结构化发现字段。未使用的顶层报告元数据被忽略，但每条发现及其证据引用仍严格验证。发现标签提供严重程度、目标、时间、处置及可展开证据；复测标签选择发现并保留每次独立尝试、说明、证据、结论和会话链接。

复测明确请求在当前保存的资产范围及操作策略下，对发现的原 URL 执行一次新的匿名 GET。它使用指定的 Worker 模型，委派自动选择时使用原先捕获的模型，并复用相同的有界公网 DNS 固定传输。不支持的验证保留为无法确认；不会新增认证、利用执行或任意工具。只有正常完成、支持的 fixed 结论、正常成功响应及引用的正常功能证据，才将处置与终态结果原子更新。原始证据保持不变。取消和重启保留中断历史，不恢复流量。

<a id="response-files-and-reports"></a>
## 响应文件与报告

新 Worker 和复测将有界响应流式保存到 `DSH_HOME/security-evidence` 下的任务级文件。模型接收带字节偏移的有界摘录，而非整个文件；大响应使用开头、中间与结尾窗口。达到捕获上限保留部分证据，不产生大小上限失败。捕获与分析完整性分别记录：完整保存的响应仍可能仅部分已读。文件缺失明确失败，旧内联证据仍可读取。部分捕获或分析不能支持复测已修复结论。

报告标签从保存记录生成最新执行的任务快照、计划操作、实际观察、发现、复测与限制，不触发推理或目标访问。它区分已确认观察、部分检查、未验证工作与不支持的操作。失败或不完整检查阻止广泛完成结论；零发现不表示资产不存在漏洞。Markdown 复制与下载使用界面相同数据。早先失败尝试保留原始历史。

<a id="planner-and-worker-token-usage"></a>
## Worker 浏览器登录

Worker 区在执行前提供浏览器登录设置。在此输入获准来源和凭据；它们保留在 Host 内存，不进入任务记录或模型提示。清除设置、更改任务授权或停止 Host 都会移除凭据。浏览器工具为每个 Worker 保留独立 Cookie；凭据不会与其他任务或来源共享。必须检查结果页面才能确认登录成功。撤销已保存的权限、范围或操作确认，会取消运行中的 Worker 并清除配置的浏览器凭据。每次工具请求也会检查当前保存的授权，因此即使遗漏变更通知，也不能继续访问。

`workerBrowserEnabled` 启用浏览器工具（默认 true），`workerBrowserHeadless` 隐藏窗口（默认 false），`workerBrowserExecutablePath` 可指定已安装 Chromium。未指定路径时，适配器优先使用已安装的 Playwright Chromium，否则使用标准 Chrome 通道。缺少浏览器会明确失败。导航、页面快照、CSS 选择器点击、普通字段填写和仅选择器私密登录，共享既有范围、HTTP 额度和操作审批。Cookie 请求属于已认证请求；保存的仅 GET 或禁止登录约束仍生效。子资源消耗同一额度，因此普通页面可能需要更大的配置请求额度。

浏览器传输记录脱敏 HTTP 观测，不持久保存原始 Cookie 或登录值。原始浏览器捕获保留配置的响应上限；公开模型摘录独立限制为 1 MiB。表单 POST 可在既有 Worker 面板等待审批。完成、取消或重启会丢弃浏览器状态。主文档 301/302/303 重定向通过新的受检导航处理；不支持 307/308 和子资源重定向。阻止 Service Worker、WebSocket、附加标签页和下载。不支持跨来源 SSO。附加认证需要所有者介入；不会自动处理 CAPTCHA 和硬件认证。

<a id="planner-and-worker-token-usage"></a>
## Planner 与 Worker 令牌用量

Planner 与 Worker 标题栏显示提供方报告的输入、缓存读取及输出令牌数。Planner 汇总独立保存规划会话的最新累计值；Worker 仅显示自身会话，包括追加回复。悬停详情包含精确计数与缓存写入。未报告的测量显示破折号，已报告零保持为零；缺失会话不会静默变成完整角色总量。初次读取与实时更新由现有会话投影提供，因此查看用量不发起模型或诊断请求，也不新增独立计量器或持久计数。这些计数不估算货币费用。

<a id="asset-coverage"></a>
## 资产覆盖

已保存任务的覆盖页将已登记资产、公司归属、任务范围和本任务的真实 HTTP 观测投影为只读关系图。已观测与范围内资产的比例仅粗略表示触达程度，不代表诊断完成或安全证明。仅有计划不计为观测，公司和仅用于连接的根节点不计入分母。范围不确定或没有范围内资产时，百分比保持未知。搜索、筛选、折叠、平移、捏合缩放及独立滚动的详情面板展示已保存的计划、Worker 与发现引用，不访问目标或模型。

<a id="planner-recovery-and-continuation"></a>
## Planner 恢复与继续

在重要发现、失败、HTTP 预算耗尽和批次完成时，已保存的 Worker 结果交给 Planner 复核。复核读取权威执行预算和发现；HTTP 预算耗尽后允许复核已保存结果，但不得继续访问目标。取消、配置变更和总时限立即停止执行。内容不变的延续项目保留明确的来源引用，因此仅共享 URL 不能完成另一个调查目标。终止执行的总结初始展开，以便直接查看已保存的停止原因。停止指引依据已保存终止状态和精确匹配的已知系统停止信息，区分额度耗尽、规划器明确请求输入及中断；不猜测未知原因，不自动恢复，也不保证能够继续。

`plannerResponseAttempts` 限制一次 Planner 请求的完整响应总次数（默认 2，范围 1–3），全部尝试共享 `plannerTimeoutMs` 截止时间。JSON 语法、结构校验及无效延续引用会在同一 Session 内请求另一次有日志的响应；策略、模型、存储、提供方、超时及取消失败按原逻辑停止。初始计划和结果复核各使用单一输出约定。延续身份仍要求调查字段完全不变，并引用唯一未解决来源项目；更改调查时必须省略 continuesItemId。禁止本地截取或拼接无效响应片段。

主 Agent 标题栏可使用 `resumeRunId` 显式继续失败、取消或中断的执行；新执行记录 `resumedFromRunId`，原历史保持不变。当前任务修订、资产和操作范围必须一致，并保留原 Planner 模型。已完成或失败的 Worker 观测直接提交复核，不再次访问目标。中断或取消的工作仍为未确认。已消耗请求数和成功复核轮次继续累计；用户显式继续会开启新的用时窗口。重启保持被动。需要输入时应检查任务设置和报告缺口，不应反复启动同一个停止决定。可选继续字段兼容已有保存记录。

`workerResponseAttempts` 同样限制一次已捕获调查后的报告响应次数（默认 2，范围 1–3）。纠正共享 Worker 模型截止时间及保留证据；模型被要求不要仅为修复 JSON 重复网络请求，进一步工具使用仍受同一运行预算和策略约束。JSON 语法、不完整代码围栏和结构校验可以纠正，证据引文违规不能。历史失败 Worker 保持不变。报告也会显示本地化请求／轮次／用时上限停止原因，包括需要输入而非错误的终态。

<a id="explicit-loopback-test-targets"></a>
## 显式环回测试目标

`localHttpOrigins` 默认 `[]`。所有者可配置最多八个规范形式的 `http://127.0.0.1:<非默认端口>` 来源用于本地测试。启动时拒绝主机别名、局域网地址、IPv6、凭据、路径、查询及片段。所选资产、精确端口、操作限制及排除优先的任务范围仍然适用。传输仅对这些精确来源跳过 DNS 并固定到 IPv4 环回，继续进行有限 HTTP 采集，不自动跟随重定向；凭据使用与非只读方法仍受已保存许可和批准检查。Planner、Worker、执行及复测准入共享此策略；模型输出不能修改允许列表。

仅测试使用的 `tests/fixtures/vulnerable-lab.ts` 导出 `startVulnerableLab({ port, fixed })`，返回来源和异步关闭函数。它仅监听 IPv4 环回并提供合成配置和用户记录。普通模式允许匿名获取这些记录，修复模式对相关路由返回 404 或 401。它不读取真实凭据、不连接外部服务、不执行命令。实际模型驱动的发现与确定性的 fixture 和传输测试分别验证。


### 管理层报告视图

已保存报告以八个纵向章节展示摘要卡、严重性和受影响资产条形图、优先发现、记录的影响／场景、修复优先级及范围限制。数字汇总任务发现，排除误报和重复；已修复保留历史但不计入活跃风险。最高活跃严重性仅为优先级指标，与调查完成度独立。没有发现不代表安全。现有技术 Markdown 导出及可展开证据保留完整记录。打开视图不执行模型或访问目标。

<a id="model-experience"></a>
## 模型体验

已保存任务通过 `securityConversations.open/send/cancel` 提供一个任务专属 Claude 会话。服务拥有持久任务与 Session 映射；现有 Session projection 和 follow 传输负责会话呈现。每个接受的轮次包含已记录的任务配置提示。明确向主 Agent 提出请求，通过五项设置检查并完成自动保存后，可经 `securityPlanning.start/read/cancel` 启动独立 Planner。版本检查拒绝已变设置；完整轮次请求身份防止重复交接。普通会话和清单完成不会自动启动规划。Worker 使用独立、有限且经过策略检查的工具执行器；不支持的自然语言约束阻止执行。普通聊天 Session 保持现有路由和权限。

安全设置在每次尝试时，通过 `EngineRunRequest.responseSchema` 传递已在上下文提示中记录的同一 JSON Schema。Claude 纯会话请求使用原生结构化输出，缺失或无效的结构化结果会在原有严格提案解析器之前被拒绝。其他引擎保留现有文本输出及严格设置验证，不声称原生结构化输出支持。格式纠正不能改变用户意图、已保存许可、模型选择或现有重试上限。

纯会话引擎禁用原生工具、MCP 服务、技能、代理和插件，拒绝原生工具钩子，SDK 初始化除 schema 专用内部结构化输出载体外声明任何工具时均拒绝。Codex 纯会话执行不可用。发送前必须保存任务编辑；重叠提交被拒绝，重试复用请求标识，取消等待持久结算。模型回答与重启恢复仍需原生账户及应用冒烟验证。

`jabberwock_security_planning` 存储域保存不可变任务与输入快照，每次尝试拥有独立 Session。完整响应可为普通 JSON 或单个完整的 JSON 代码围栏，字段仍严格校验。通过校验的方案生成待处理、未批准的调查项；未知资产 ID 将拒绝方案。稳定请求 ID 防止重复提交，每个任务仅允许一个活动 Planner，在完成前接受的取消阻止延迟成功结果。重试失败保留历史方案，重启后未完成尝试标记为中断。插件配置 `plannerTimeoutMs` 限制规划时长（默认 180000 ms）。规划不会调用目标 HTTP、Shell 或 Worker 执行。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与待办工作

Worker 运行有限工具循环，包含经过检查的 HTTP、证据访问和私有文件。认证与非只读请求需要已保存的许可和批准；重定向需要新的检查请求。离线命令仅支持 macOS 单进程。不支持 Codex Worker；真实 DeepSeek 模型尚未验证。除所有者精确配置的环回测试来源外，私网仍被阻止。报告汇总已保存证据，不代表全面漏洞覆盖或独立验证的业务损失。主聊天控制共享同一组任务服务负责人；Codex 主聊天控制不可用。

修复报告将复查运行 ID 保留为历史参考，不作为导航链接；对应结果可能已删除。当前用户委派会拒绝明确的否定请求，包括拒绝开始调查或规划。

## 供应链检查

工作区 Security 页面提供任务式供应链检查列表。开始操作立即创建运行中行，并启动无需大模型的固定 npm／pnpm 锁文件公告检查。打开一行会嵌入其现有普通 Session 对话与报告，不复制已保存历史。展示进度、取消、包名／版本发现、依赖范围和复用现有报告组件的可展开事实报告。共享工作区锁保留实际共享范围。保存的提示消息携带已验证运行快照和明确历史可见标志；完成结果在重启后保留，不自动扫描或启动模型轮次。每个历史行提供“查看报告”（与打开该行相同的详情）和经确认的“删除”。删除通过工作区所有者的 `securitySupplyChain.deleteRun` 逻辑隐藏一次已结束的运行：该运行不再出现在列表、读取、修复和共享对话中，重启后仍保持隐藏。重启后恢复的运行会先在不触发模型轮次的情况下重新打开其会话，再记录删除；若失败则不记录任何内容，可重试删除。若会话日志刷盘失败，删除结果未知：该运行保持隐藏并显示错误，重复删除只有在新一次刷盘成功后才会确认。已删除运行的 `requestId` 不能再启动新检查。运行中的检查或修复不能删除，须先停止。会话日志保留该运行的全部早期快照作为证据，同一会话中的其他运行保留，项目清单、锁文件和修复恢复文件不会被触碰。

扫描器向 npm 注册表批量公告 API 发送锁定包名和版本。可选公开 GitHub 公告查询仅向固定 API 主机发送公开 GHSA ID，不使用 token。不上传源码、环境文件正文或凭据文件正文。可选元数据获取失败明确保留未知信息。扫描器不安装、更新或修复依赖，也不执行项目代码。匹配已知公告不证明代码可达性、应用可利用性或不存在未知脆弱性；未完成或失败检查不代表安全。

单项与批量修复是针对已完成检查的独立、明确所有者操作。初始修复支持具有公开直接 semver 依赖的独立项目；共享／工作区、私有、override 及不支持的依赖定义需手动处理。没有定义指纹的旧扫描需要重新检查。Host 在项目之外暂存固定 npm／pnpm 仅锁文件命令，禁用脚本／钩子并隔离包管理器配置／环境。刷新全部公告比对、验证所选候选版本，并检查原 manifest／锁文件哈希，再备份应用定义文件并复扫。不接受任意命令或调用方指定版本。

修复记录保留所选变更、全部锁定图版本变更摘要及各文件哈希，不作为完整源文件 diff 展示。原始字节及各文件应用进度保存在仅所有者可访问的恢复目录。取消、编辑冲突或部分应用保持明确；自动回滚不会覆盖更新的所有者编辑。修复仅更新 package.json 与锁文件：node_modules 安装、应用构建及功能健康检查仍未运行。公告清除不代表应用健康成功。重启恢复时，运行中的修复变为中断，不自动回放。

## 产品安全技能

应用在包资源中包含 `security-task`、`security-plan`、`security-investigate`、`security-status` 和 `security-report`。Host provider 将它们注册到共享技能注册表，不依赖所选 Workspace 或项目的 `.agents` 目录。现有 `skill` 加载器发布说明，并在选择后一起加载工作流和单一共享规则资源。规划使用 `security_control` 的仅规划操作，不启动 Worker。原生引擎的发现和工具可用性取决于订阅引擎集成。
